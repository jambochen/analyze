# 期望勝率與實際得分口稿

每段依序寫頁標題、預估字數，之後是口稿。
投影片上的數字一律由 `outputs/tables/` 的 CSV 讀入；口稿指著投影片上的數字解讀，不另念數字。
本次的推論把各局當成獨立（`p_naive`、`se_iid`），對局之間的相依留到下一次報告處理。

## Glicko 的期望得分
字數：170

配對系統不論是為了追求公平還是留住玩家，都要先依雙方的等級分估出一個期望勝率，所以要先知道這個期望勝率是否符合實際情況。

Lichess 的等級分系統是 Glicko。系統另外替每個帳號記一個 RD，代表這個等級分有多不可靠。新帳號從 1500 分、RD 350 開始，下得越多，RD 越小。賽後更新等級分時，系統用的就是投影片上這條考慮 RD 的公式。

## Elo 的期望得分
字數：60

但配對只看等級分差，不管 RD。把 RD 拿掉，Glicko 的公式就退化成 Elo。所以配對隱含的勝率是 Elo 的，我們先檢驗它。

## 以 logistic 迴歸估計 Elo 的參數

## 估計的 $\alpha$ 與 $\beta$
字數：140

這裡只取雙方 RD 都低於 110 的老手對局。$\alpha$ 是分差 0 時白方的優勢，$\beta$ 是分差的斜率。右邊的圖，黑線是 Elo，色線是配適的結果。

表上 $\alpha$ 的區間都在 0 以上，$\beta$ 的區間都在 1 以下，兩者都偏離 Elo。也就是說，白方有先手優勢，強弱的差距也沒有系統說的大。

## 三類結果的有序模型
字數：170

剛才的迴歸只看平均得分，但玩家看到的是勝、和、負三種結果，而 Elo 對和局沒有說法。所以改成直接對三類結果建模，用有序 logistic。

圖上這條曲線代表白方這一局的發揮，落在右邊是白勝，中間是和，左邊是負。曲線的位置由分差和先手決定，中間那段的寬度決定和局有多常見。

位置和寬度各自隨等級分變，所以「白方優勢隨等級變」和「和局率隨等級變」可以分開檢定。

被問到「分差對勝與不輸的作用是否相同」：以同樣的概似比檢定檢查過，三種速度都不拒絕。

## 和局與白方優勢
字數：230

這張圖不經模型，只取幾乎勢均力敵的對局，直接看和局率和白方的平均得分。

左邊的和局率隨等級明顯上升，看投影片上低分和高分的兩個數字，差了一倍以上，Classical 上升最快。Elo 把和局記成 0.5，隱含和局多寡跟實力無關，這不成立。

右邊的白方得分一直略高於一半。投影片上把它換算成等級分，相當於白方先手多了這麼多分，而且不隨等級改變。這兩點模型都要納入：和局率隨等級變，再加上先手。和局率整體不高，對期望得分影響不大，但對勝、和、負三個機率的分配不能忽略。

## 斜率 $\beta$ 與累計局數
字數：150

剛才的 $\alpha$ 與 $\beta$ 只取老手對局。這裡拿掉限制，依雙方中較少的那一方已經下過幾局，分組估斜率。

第 0 局，也就是帳號的第一局，斜率最低、離 1 最遠；之後一路上升，到幾十局趨穩。有兩件事要分開處理：新帳號偏得最多，等級分還沒有收斂；趨穩之後，右端的斜率仍低於 1。先處理新帳號，後者留到後面。

## 依 Glicko-2 重算 RD
字數：190

剛才的分組只用累計局數代表新手的程度。更直接的量是前面介紹過的 RD：新帳號從 350 開始，每下一局縮小一些。公開資料沒有 RD，所以照 Lichess 當時的原始碼，從每個帳號的第一局開始一局一局重算。

重算能不能信，可以直接驗：算出的等級分要等於表頭記的。投影片上是相符的比例，雙方帳號歷史都完整時更高。不相符的主要是資料開始前就存在的帳號，起點未知，以表頭的等級分校正後再往下算。

## 新手期的界定
字數：440

有了 RD，新手期就能用系統自己的標準界定。Lichess 從 2015 年 6 月起，在介面上把 RD 110 以上的等級分標示為「尚未確定」；門檻取自原始碼，不是看了資料才定的。2014 年還沒有這個標示，所以這是把後來的規則套回 2014 年。雙方任一方還在門檻之上，這局就算新手對局。

Lichess 閒置時不增加 RD，所以 RD 幾乎只由下過的局數決定。表上第一欄是一半帳號跌破門檻的局數，RD 門檻其實就是「下滿十幾局」。新手對局在 arena 比較多，下一次的分析以 arena 為主，新手的處理對它特別重要。

左邊的圖依 RD 分組估斜率。斜率隨 RD 下降而連續上升，越過 110 的那一步和相鄰幾組差不多，看不出跳躍，要到 RD 遠低於 110 才接近其他對局的值。

所以 110 是系統宣稱「等級分可信」的約定，不是偏差消失的界線。偏差連續收斂，用任何門檻排除新手，門檻另一側都還留著偏差。因此新手對局不排除，模型加入一個隨 RD 變化的項；110 只用來描述新手對局有多少。只加 RD 項夠不夠，要看累計局數那張圖留下的另一件事：老手。

被問到「為什麼是 110」：門檻換成 RD 100 或雙方皆滿 30 局，老手對局的斜率 $\beta$ 幾乎不變（`novice_period_cox.csv`）；RD 隨局數的軌跡見 `expected_score_slides_rd`，RD 門檻與局數門檻的 kappa 見 `novice_period_agreement.csv`。

被問到「110 處有沒有斷點」：今天只看了圖。RD 幾乎由下過的局數決定，所以是一團一團的，每個局數一團，越過 110 就在第 13、14 局之間。在 RD 上配平滑曲線再檢定跳躍，結果會隨曲線的設定改變；要檢定應改在局數上，每一局各估一個斜率，檢定越過門檻的那一步是否比其他步大。這不影響今天的結論，因為 110 沒有拿來切樣本。

## 老手的斜率為何低於 1
字數：470

回到累計局數那張圖留下的問題：趨穩之後，斜率為什麼仍低於 1。

直覺的解釋是等級分有雜訊。迴歸課講過，解釋變數有量測誤差，斜率會往 0 衰減，就是表上第一列。

但等級分不是實力加雜訊，而是系統根據過去所有結果估出的實力的事後平均。系統設定正確時是第二列：誤差跟等級分無關。在線性迴歸裡，這種誤差不會讓斜率變小。

期望得分是 logistic，情況不同：對這個誤差取平均之後，期望得分會往一半靠，斜率跟著變小，就是第三列；Glicko 公式裡考慮 RD 的那一項就是這麼來的。所以要問的是，這個衰減夠不夠解釋觀察到的斜率。

右邊的圖回答這件事。左格是 Elo 的期望得分，右格改用 Glicko 的期望得分，已經算進這個衰減。老手的 RD 小，衰減也小，兩格幾乎一樣：仍是弱方在 0 以上、強方在 0 以下，圖例上的斜率只上升一點，仍明顯低於 1。

所以老手的斜率小於 1，不能用等級分的不確定來解釋。對模型的意思是：只靠 RD 讓期望得分往一半收縮不夠，分差自己的斜率也要留著。原因指向等級分隨每一局更新的方式，但更新規則錯在哪個方向，單看斜率分不出來，要看剛輸、剛贏之後的期望勝率，留到下一次。

## 三個模型
字數：170

到這裡，每一種錯都對應到一項，現在把它們拼起來，並檢查每一項是不是真的需要。

第一個是剛才的有序 logistic，有分差、平均等級分、先手，但不管 RD。

第二個是 Glicko 自己的預測式，只靠 RD 讓期望得分往一半收縮。它沒有和局、沒有先手，我們替它補上。

第三個把兩者合起來。右下的圖顯示前兩個都是第三個的簡化版，所以可以直接用概似比檢定比較。

## 三個模型的比較
字數：390

左邊的表，兩個受限模型在三種速度都被拒絕，統計量遠大於自由度。排除資料開始前就存在的帳號，結論相同。有序 logistic 被拒絕，表示 RD 帶有分差和先手以外的資訊；Glicko 被拒絕，表示只靠 RD 收縮不夠，斜率偏差、和局與先手都還在。

檢定說哪個不對，但沒說差多少，所以另做樣本外的預測：上半年估計，下半年全部對局拿來評分。評分用對數分數，看模型給實際發生的結果多少機率，越小越好。

最下面一行先交代 Elo 本身。Elo 沒有和局機率，我們替它補上和局，期望得分不變；有序 logistic 在三種速度都比它好。

右邊的圖再和有序 logistic 比。加入 RD 的模型在三組都最好，改善集中在新手。Glicko 形式幫了新手，在老手上卻比有序 logistic 差：它承認的不確定性方向對、幅度不對。

所以後面所有分析的期望勝率，都以加入 RD 的有序 logistic 計算，這個選擇有樣本外的依據，不只靠檢定。

## 本次的結論
字數：220

上面是最後的模型，表上每一列是一項，右邊是它修的那一種錯。

分差的斜率修的是高估強方。三類結果與隨等級變的和局區間，修的是和局；先手項修的是白方的固定優勢。RD 那一項修的是新帳號，偏差隨 RD 連續縮小，所以新手不排除。最後一列是老手：算進 RD 之後斜率仍低於 1，所以分差項和 RD 項要同時留著。

兩個受限模型都被拒絕，表示這幾項缺一不可；樣本外的預測也是它最好，後面計算期望勝率用的就是這個模型。換到電競，定級賽結束、系統說分數已經穩定，期望勝率不一定準。

## 本次的限制
字數：200

今天有兩個地方沒有處理。

第一，檢定和區間都把每一局當成獨立，但同一位玩家下了很多局，各局共用同一個真實實力；一局又牽涉兩位玩家，對局彼此串連。不獨立時，檢定會太容易拒絕，區間也會太窄。樣本外的對數分數不需要獨立的假設，模型的選擇不受影響。下一次處理相依後重新檢定。

第二，大廳混有好友對戰，好友之間可能互相了解，期望與實際的差距可能不同。來源要從 Lichess API 逐局查詢，下載完成後分開重估。

## 下一次的問題
字數：340

玩家關心的是：輸了要不要停。今天看到期望勝率依對局條件就有系統性的偏差，但換一個更好的模型就修正了，跟玩家當下的狀態無關，停手幫不上忙。停手要有用，偏差必須跟著狀態走。

下一次問三件事，每一件都拿今天拼出的模型當期望。第一，剛被分到強對手，多半也就剛輸了，下一局是否低於期望。第二，輸的人比較少繼續下，下一局只在續下時才看得到，要處理這個選擇。第三，今天老手的斜率指向更新規則，剛輸、剛贏之後等級分是否失準，檢驗它錯在哪個方向。

這三件都有一個前提：上一局對手的強弱必須跟玩家當天的狀態無關，量到的差別才能歸給上一局。2014 年 arena 的規則是隨機配對，下一次先用資料驗證這件事。

三件做完，最後一次把結果做成修正後的勝、和、負機率與停止規則的回測，再用保留的 2015 年資料驗證一次。
