# 期望勝率與實際得分口稿

每段依序寫頁標題、預估字數，之後是口稿。
投影片上的數字一律由 `outputs/tables/` 的 CSV 讀入；口稿指著投影片上的數字解讀，不另念數字。
本次的推論把各局當成獨立（`p_naive`、`se_iid`），對局之間的相依留到下一次報告處理。

## 資料來源
字數：80

Lichess 程式碼開源，等級分公式和配對機制都查得到。三種匹配方式裡，只有 arena 由系統指派、不看等級分，所以 arena 的對手是誰，跟玩家當下的狀態沒有關係。

被問到「為什麼用西洋棋，不直接用電競資料」：電競的 MMR、配對規則與每局的期望勝率都不公開，外部無法檢驗。Lichess 的等級分公式、配對規則與每局開始前的等級分全部公開，資料授權也是 CC0。

被問到「arena 真的是隨機配對嗎」：2014 年的原始碼裡，arena 配對不用等級分。初步檢查在同一批空閒的玩家裡重新打亂對手，實際的分差和打亂後的一致；正式結果放在下一次。

## 資料與樣本
字數：100

我們用 2014 年全年的 rated 對局。三種速度各有自己的等級分，所以需要分開估。

表上最後一欄是 arena；其餘是大廳與好友對戰。2015 年前幾個月的 arena 留著不看，等所有分析定案後才用一次。

被問到「為什麼只用 2014 年」：2014 年整年的 arena 都是隨機配對。2015 年 4 月 20 日起 arena 改成會輕微參考等級分，那之前的幾個月留作驗證。

被問到「2015 年的資料為什麼不能先看」：看過結果再定方法，驗證就不再獨立。所以要等分析定案、把假設和判定規則寫下來之後，才用一次。

被問到「速度類別怎麼分」：照 Lichess 當時計分的規則，用估計時長分。月檔上標的類別是後來用新規則補標的，會把不同的等級分混在一起，所以不用。

## 欄位的用途
字數：60

我們只用比賽前就知道的資訊來算期望得分：雙方的等級分、這局的時間設定、是不是 arena。結果只拿來對照期望得分準不準。

被問到「為什麼不用表頭的等級分變動」：`WhiteRatingDiff`、`BlackRatingDiff` 是賽後依結果算出的，放進去等於用結果預測結果。

被問到「帳號怎麼用」：只用來串起同一個人的歷史，算累計局數和 RD；報告不呈現任何帳號。

## Glicko 的期望得分
字數：170

配對系統不論是為了追求公平還是留住玩家，都要先依雙方的等級分估出一個期望勝率，所以要先知道這個期望勝率是否符合實際情況。

Lichess 的等級分系統是 Glicko。系統另外替每個帳號記一個 RD，代表這個等級分有多不可靠。新帳號從 1500 分、RD 350 開始，下得越多，RD 越小。賽後更新等級分時，系統用的就是投影片上這條考慮 RD 的公式。

被問到「資料裡有 RD 嗎」：公開資料沒有。我們照 Lichess 當時的原始碼，從每個帳號的第一局開始重算，算出的等級分和表頭記的大多相符（`glicko_replay_era.csv`）。

被問到「Glicko 和 Glicko-2 差在哪」：Glicko-2 多記一個波動度，影響 RD 每局怎麼更新；預測一局的期望得分，形式相同。

## Elo 的期望得分
字數：60

但配對只看等級分差，不管 RD。把 RD 拿掉，Glicko 的公式就退化成 Elo。所以配對隱含的勝率是 Elo 的，我們先檢驗它。

被問到「系統用 Glicko 更新，為什麼檢驗 Elo」：配對和玩家看到的都只有分數，所以配對隱含的是 Elo 的勝率。Glicko 的版本放在後面的三個模型裡比。

被問到「400 是怎麼來的」：這是 Elo 的慣例尺度，分差 400 分時強方的期望得分約九成；Lichess 的等級分用同一個尺度。

## 得分偏差
字數：80

這張圖是每個分差下，實際得分和期望得分的差距。期望得分若是準的，每一組都應該貼著 0。但兩端的點都離 0 好幾個區間寬：弱方贏得比系統說的多，強方贏得比系統說的少。

被問到「實際得分是勝率嗎」：勝記 1、和記 0.5、負記 0 的平均，所以和局也算進去。

被問到「區間怎麼算的」：把每一局當成獨立。同一位玩家下很多局，區間會太窄，下一次處理；但偏差離 0 好幾個區間寬，方向不會因此改變。

## 以 logistic 迴歸估計 Elo 的參數
字數：80

Elo 的公式本身就是一條 logistic 曲線。既然如此，就把它當成 logistic 迴歸來估。

因為有和局，得分不是只有 0 和 1，所以用 quasi-likelihood。

被問到「為什麼不用一般的 logistic 迴歸」：一般的 logistic 假設結果只有 0 和 1。quasi-likelihood 只要求平均的形式對，和局可以直接代 0.5。

被問到「為什麼用 score test」：它只需要在 Elo 成立的假設下計算，不必另外估模型；Wald 檢定在 logistic 上會受參數的寫法影響。

被問到「和局讓變異比勝負小，有影響嗎」：變異照只有勝負來算會偏大，區間偏寬、檢定偏保守，所以拒絕的結論只會更可信。

## 估計的 $\alpha$ 與 $\beta$
字數：160

這裡只取雙方 RD 都低於 110 的老手對局，110 是 Lichess 系統自己定的門檻。$\alpha$ 是分差 0 時白方的優勢，$\beta$ 是分差的斜率。右邊的圖，黑線是 Elo，色線是配適的結果。

表上 $\alpha$ 的區間都在 0 以上，$\beta$ 的區間都在 1 以下，兩者都偏離 Elo。也就是說，白方有先手優勢，強弱的差距也沒有系統說的大。

被問到「為什麼只用老手對局」：新帳號的等級分還沒收斂，偏差另有來源，混在一起會把兩種錯混為一談。110 是 Lichess 系統自己定的門檻；換門檻結果會不會變，下一次確認。

被問到「是不是只有某一群玩家這樣」：依等級分區間、arena 或大廳、2014 年 7 月底等級分重算前後分開估，方向都一樣（`calibration_cox.csv`）。

被問到「斜率為什麼低於 1」：下一次從剛輸、剛贏之後的等級分檢驗，看等級分的更新是不是出了問題。

## 和局率與等級
字數：180

剛才的迴歸只看平均得分，一場和局和一勝一負平均起來一樣，看不到和局。這張圖不經模型，只取幾乎勢均力敵的對局，直接看和局率。

和局率隨等級明顯上升，看投影片上低分和高分的兩個數字，差了一倍以上，Classical 上升最快。Elo 把和局記成 0.5，隱含和局多寡跟實力無關，這不成立。和局率整體不高，對期望得分影響不大，但對勝、和、負三個機率的分配不能忽略。

被問到「為什麼只取分差 25 分以內」：要看和局率隨等級怎麼變，得先把分差固定住。分差越大和局越少，不固定的話，各等級的分差分布不同，會混進來。

被問到「Classical 的和局率為什麼上升最快」：我們沒有檢驗原因，這張圖只用來說明和局要單獨建模。

## 三類結果的有序模型
字數：150

所以改成直接對三類結果建模，用有序 logistic，這也是玩家實際看到的：勝、和、負。

圖上這條曲線代表白方這一局的發揮，落在右邊是白勝，中間是和，左邊是負。曲線的位置由分差和先手決定，中間那段的寬度決定和局有多常見。

位置和寬度各自隨等級分變，所以「白方優勢隨等級變」和「和局率隨等級變」可以分開檢定。

被問到「分差對勝與不輸的作用是否相同」：以同樣的概似比檢定檢查過，三種速度都不拒絕。

被問到「為什麼不用多項 logistic」：勝、和、負有順序，有序模型用一個優勢就能描述「越強越容易贏、和局在中間」，參數也少；多項 logistic 不用這個順序。

被問到「曲線為什麼用 logistic」：為了和 Elo 用同一個尺度，結果可以直接對照。

## 斜率 $\beta$ 與累計局數
字數：120

剛才的 $\alpha$ 與 $\beta$ 只取老手對局。這裡拿掉限制，依雙方中較少的那一方已經下過幾局，分組估斜率。

第 0 局，也就是帳號的第一局，斜率最低、離 1 最遠；之後一路上升，到幾十局趨穩。新帳號偏得最多，等級分還沒有收斂，這部分交給模型裡的 RD 項。

被問到「累計局數怎麼算」：2013 年 1 月起，同一速度類別下過的局數。2013 年 1 月就已存在的帳號會低估，分開比較結果相近（`calibration_cox.csv`）。

被問到「為什麼看雙方中較少的那一方」：一局的偏差主要來自比較不熟的那一方，他的等級分還沒收斂。

被問到「新帳號為什麼偏這麼多」：新帳號從 1500 起算，等級分還沒走到真正的實力，系統說的分差不可靠。

## 三個模型
字數：170

到這裡，每一種錯都對應到一項，現在把它們拼起來，並檢查每一項是不是真的需要。

第一個是剛才的有序 logistic，有分差、平均等級分、先手，但不管 RD。

第二個是 Glicko 自己的預測式，只靠 RD 讓期望得分往一半收縮。它沒有和局、沒有先手，我們替它補上。

第三個把兩者合起來。右下的圖顯示前兩個都是第三個的簡化版，所以可以直接用概似比檢定比較。

被問到「為什麼不用 AIC 比較」：AIC 的懲罰項要假設各局獨立、模型正確。樣本夠大，可以直接用樣本外的資料比。

## 三個模型的比較
字數：370

左邊的表，兩個受限模型在三種速度都被拒絕，統計量遠大於自由度。有序 logistic 被拒絕，表示 RD 帶有分差和先手以外的資訊；Glicko 被拒絕，表示只靠 RD 收縮不夠，斜率偏差、和局與先手都還在。

檢定說哪個不對，但沒說差多少，所以另做樣本外的預測：上半年估計，下半年全部對局拿來評分。評分用對數分數，看模型給實際發生的結果多少機率，越小越好。

最下面一行先交代 Elo 本身。Elo 沒有和局機率，我們替它補上和局，期望得分不變；有序 logistic 在三種速度都比它好。

右邊的圖再和有序 logistic 比。加入 RD 的模型在三組都最好，改善集中在新手。Glicko 形式幫了新手，在老手上卻比有序 logistic 差：它承認的不確定性方向對、幅度不對。

所以後面所有分析的期望勝率，都以加入 RD 的有序 logistic 計算，這個選擇有樣本外的依據，不只靠檢定。

被問到「檢定都拒絕，是不是只因為樣本大」：樣本大確實什麼都容易顯著，所以另看樣本外的預測；完整模型在每一組都最好，改善不只是統計上的。

被問到「為什麼按時間切，不隨機切」：模型要拿來預測之後的對局，同一位玩家也會出現在兩邊。用前半年預測後半年，比較接近實際的用法。

被問到「新手怎麼分組」：任一方 RD 在 110 以上，同樣是 Lichess 系統的門檻。

## 本次的結論
字數：190

上面是最後的模型，表上每一列是一項，右邊是它修的那一種錯。

分差的斜率修的是高估強方。三類結果與隨等級變的和局區間，修的是和局；先手項修的是白方的先手優勢。RD 那一項修的是新帳號，偏差隨局數連續縮小，所以新手不排除。

兩個受限模型都被拒絕，表示這幾項缺一不可；樣本外的預測也是它最好，後面計算期望勝率用的就是這個模型。換到電競，定級賽結束、系統說分數已經穩定，期望勝率不一定準。

被問到「對營運方有什麼建議」：我們研究的是配對系統的輸入，也就是期望勝率，不是配對演算法本身。但對營運方有一個直接的意涵：判斷一局公不公平，應該用修正後的期望勝率，尤其是新帳號。至於該配勢均力敵還是懸殊的對局才能留住玩家，我們檢驗過 EOMM 這類以留住玩家為目標的配對模型，它的關鍵假設在資料上不成立，具體策略需要另做模擬。

被問到「換到電競能類推多少」：電競的 MMR 也是依勝負更新的分數，定級賽之後同樣說分數穩定，所以「高估強方、新帳號偏差大」的風險可以類推。但電競多是團隊賽、排隊配對、沒有和局，偏差的大小不能直接搬。

## 本次的限制
字數：200

今天有兩個地方沒有處理。

第一，檢定和區間都把每一局當成獨立，但同一位玩家下了很多局，各局共用同一個真實實力；一局又牽涉兩位玩家，對局彼此串連。不獨立時，檢定會太容易拒絕，區間也會太窄。樣本外的對數分數不需要獨立的假設，模型的選擇不受影響。下一次處理相依後重新檢定。

第二，大廳混有好友對戰，好友之間可能互相了解，期望與實際的差距可能不同。來源要從 Lichess API 逐局查詢，下載完成後分開重估。

被問到「處理相依之後結論會變嗎」：已經用修正過的檢定試算，兩個受限模型仍被拒絕（`expected_score_baselines_tests.csv`）；下一次正式呈現。

被問到「好友對戰影響多大」：要等來源下載完才能分開。arena 沒有好友對戰，而 arena 和大廳分開估的方向一致（`calibration_cox.csv`）。

## 下一次的問題
字數：320

玩家關心的是：輸了要不要停。今天看到期望勝率依對局條件就有系統性的偏差，但換一個更好的模型就修正了，跟玩家當下的狀態無關，停手幫不上忙。停手要有用，偏差必須跟著狀態走。

下一次問三件事，每一件都拿今天拼出的模型當期望。第一，剛被分到強對手，多半也就剛輸了，下一局是否低於期望。第二，輸的人比較少繼續下，下一局只在續下時才看得到，要處理這個選擇。第三，剛輸、剛贏之後等級分是否失準。

這三件都有一個前提：上一局對手的強弱必須跟玩家當天的狀態無關，量到的差別才能歸給上一局。2014 年 arena 的規則是隨機配對，下一次先用資料驗證這件事。

三件做完，最後一次把結果做成修正後的勝、和、負機率與停止規則的回測，再用保留的 2015 年資料驗證一次。

被問到「最終想分析的是什麼，只是準或不準嗎」：最終想回答的是玩家剛輸之後該不該停。如果系統的期望勝率是準的，每一局又互相獨立，那怎麼停都一樣；停手要有用，期望勝率必須在剛輸之後錯。要量這件事，得先有一個不受對局條件干擾的期望，今天做的就是這個基準。最後的成果是修正後的勝和負機率，以及停止規則的回測。

被問到「剛被分到強對手為什麼會影響下一局」：被分到強對手比較容易輸，輸了可能影響狀態，下一局就可能低於期望。對手是隨機分的，所以量到的差別可以歸給上一局。
