# 期望勝率與實際得分口稿

每段依序寫頁標題、預估字數，之後是口稿。
投影片上的數字一律由 `outputs/tables/` 的 CSV 讀入；口稿指著投影片上的數字解讀，不另念數字。
本次的推論把各局當成獨立（`p_naive`、`se_iid`），對局之間的相依留到下一次報告處理。

## 資料來源
字數：160

資料來自一個由非營利組織經營的線上西洋棋平台，免費，程式碼也開源。官方每個月公開一份資料庫，記著雙方賽前的等級分和這局的結果。等級分系統是 Glicko-2，公式和配對機制都能從源碼中查得到。

玩家找對手有三種方式。大廳是自己從列表挑，可以設等級分範圍；好友對戰是指定對手。只有 arena 由系統指派、不看等級分，所以 arena 的對手是誰，跟玩家當下的狀態沒有關係。

## 資料與樣本
字數：90

我們用 2014 年全年的 rated 對局。三種速度各有自己的等級分，所以需要分開估。

表上最後一欄是 arena；其餘是大廳與好友對戰。2015 年前幾個月的 arena 留著不看，等所有分析定案後才用一次。

## 欄位的用途
字數：100

我們只用比賽前就知道的資訊來算期望得分：雙方的等級分、這局的時間設定、是不是 arena。結果只拿來對照期望得分準不準。帳號和開局時間用來把同一個人在同一場 arena 裡的對局排成一串，看上一局的結果和之後有沒有再下。

## Glicko 的期望得分
字數：130

配對系統不論是為了公平還是留住玩家，都要先估出雙方的期望勝率，所以要先檢查它準不準。

Lichess 的等級分系統是 Glicko。系統另外替每個帳號記一個 RD，代表這個等級分有多不可靠。新帳號從 1500 分、RD 350 開始，下得越多，RD 越小。賽後更新等級分，用的是投影片上這條含 RD 的公式。

## 以 logistic 迴歸估計 Elo 的參數
字數：70

Elo 的公式本身就是一條 logistic 曲線，所以可以直接當成 logistic 迴歸來估。因為有和局，得分不只 0 和 1，所以用 quasi-likelihood。

## 估計的 $\alpha$ 與 $\beta$
字數：120

這裡只取雙方 RD 都低於 110 的對局，110 是 Lichess 自己定的門檻。$\alpha$ 是分差 0 時白方的優勢，$\beta$ 是分差的斜率。右邊的圖，黑線是 Elo，色線是配適的結果。

表上 $\alpha$ 的區間都在 0 以上，$\beta$ 的區間都在 1 以下：白方有先手優勢，強弱的差距也沒有系統說的大。

## 三類結果的有序模型
字數：120

改用有序 logistic，直接對玩家實際看到的勝、和、負建模。

圖上這條曲線代表白方這一局的發揮，落在右邊是白勝，中間是和，左邊是負。曲線的位置由分差和先手決定，中間那段的寬度決定和局有多常見。

位置和寬度各自隨等級分變，所以「白方優勢隨等級變」和「和局率隨等級變」可以分開檢定。

## 斜率 $\beta$ 與累計局數
字數：60

接著依帳號累計的局數分組，各組各自估斜率。

第 0 局，也就是帳號的第一局，斜率最低；之後一路上升，到幾十局趨穩，但 200 局以上仍在 1 以下。

## 三個模型
字數：150

到這裡，Elo 有三件事沒考慮：先手、和局，還有水平波動。前兩件剛才的有序 logistic 已經放進去，分差的影響也改由資料估。水平波動，Glicko 的 RD 算是有考慮。

第一個模型是有序 logistic，不管 RD。第二個是 Glicko 自己的預測式，只靠 RD；它沒有和局和先手，我們替它補上。第三個把兩者合起來，前兩個都是它的簡化版，所以可以用 LRT。

## 三個模型的比較
字數：130

我們用 2014 年全年的資料估計，LRT 顯示兩個簡化版在三種速度都被拒絕。

有序 logistic 和 Glicko 形式彼此不是簡化關係，不能用 LRT，所以最右欄用 AIC 比：三種速度都是 Glicko 形式較好，但兩者都不如加入 RD 的有序 logistic。

後面的期望勝率都用這個模型算。

## 樣本外的校準
字數：160

為了看模型在估計樣本以外是否仍準，我們用上半年估計、下半年評估。淡色虛線是 Elo，實線是加入 RD 的有序 logistic。

左圖，我們的模型幾乎貼著 0。右圖依累計局數看斜率：十局以後都貼著 1，但第 0 局仍不到 1，Bullet、Blitz 的前幾局又修過頭；RD 修正的方向對，形狀還不對。中間是和局：實際和局整體比預測多一點，只有 Bullet 在預測和局較多的那端反而高估。

## 上一局與本局的轉移
字數：200

arena 是有固定時長的錦標賽，玩家隨時可以加入，也隨時可以走。每下完一局就回到等待區，系統從同時空閒的人裡再配一個對手，所以同一個人在一場裡會連下好幾局。

我們用一階 Markov 鏈看上一局的結果跟這一局有沒有關係。

每根柱子是一列轉移機率：上一局是這個結果的人，這一局輸、和、贏各佔多少。上一局輸了的人，這一局輸的比例最高；上一局贏了的人，這一局贏的比例最高。

這可能是輸了心態受影響，也可能只是這些人本來就比對手弱，或等級分跟不上當天的實力。

## 連輸、連贏之後的離開
字數：100

輸了之後離開的比例明顯高於贏了之後，連輸兩局又比只輸一局更常離開；連贏則越贏越少人走。所以上一頁「上一局輸」那一列，只算到輸了也不走的人。

右下的灰字要注意：連輸三局的人，是前兩次輸了都沒走的人，各點不是同一群人。

## 本次的結論與限制
字數：190

我們找到一個模型，能用雙方賽前的等級分與 RD，比 Elo 更準地估勝、和、負的機率。

還有一些事沒處理。第一，檢定和區間都假設各局獨立，但同一位玩家下了很多局，這些局可能彼此相關。

第二，新帳號的最初幾局還不準。RD 照 Lichess 的算法重算，調整分差的方式也照 Glicko，我們只估了整體要用多少；這套算法本身可能不符合新帳號的實際情況。

第三，上一局的結果和這一局有關，但我們只往前看一局，也只看得到輸了還繼續下的人。

## 附錄：切點隨平均等級分的形式
字數：100

這頁回答切點為什麼取二次。每個點是把平均等級分分組後各自估的值，不預設形式；虛線是直線，實線是二次。和局帶寬在 Classical 和 Blitz 明顯彎曲，所以需要二次；先手優勢的點大致排成直線，二次項沒有資料支持。
