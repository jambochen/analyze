### 品質判準：什麼該排除

- **合成資料**：2024 年後上傳、檔案 < 1 MB、標題含「Prediction Dataset」、
  usability 1.0 但無來源說明。多為 LLM 生成
- **教學經典集**：Boston Housing、Titanic、Iris。被做過上萬次，無新穎度
- **搬運版本**：同一底層資料有數十個重複上傳。**檔案大小完全相同即同源搬運**
  （顧客流失方向出現多筆 175,722 至 175,782 bytes 的檔案，全是同一份 IBM Telco
  教學資料）。若採用須追溯原始出處
- **課程作業成品**：特徵為票數個位數、標題含 Capstone 或 Cleaned。清理過程不透明
- **授權欄位不可信**：由上傳者自填，常見 Unknown 或誤填。政府資料的搬運版
  一律回原始平台確認條款
- **隱私敏感領域的「真實」資料要特別懷疑**：病患臨床紀錄受法規保護不會公開，
  此類高票資料集預設是合成。政府的*行政給付*紀錄（如巴西 SIH）才是該領域
  唯一可信的型態

### 品質判準：什麼值得信

能用的資料集集中在三類來源：

1. **機關作業系統直出**（Chicago CLEAR、CDC BRFSS、UK Power Networks）。
   特徵是有官方 codebook、逐欄定義、免責聲明。**免責聲明本身是品質訊號**——
   願意講清楚限制的資料，限制是已知的
2. **有論文背書的研究資料集**（US Accidents 附兩篇 SIGSPATIAL 論文）
3. **加值型資料工程者**：專業者將多個上游來源正確整合後發布。
   `arimancy` 的電網與航班系列是本專案確認的例子

第三類的辨識訊號值得記下——**描述文字談方法論而非行銷**：明確交代每個上游
來源與授權、說明 join 的技術決策、插補有旗標欄位而非默默填補、附資料字典、
**主動揭露對自己不利的限制**。若描述出現 ablation、provenance、
known limitations、leakage 等詞且有具體數字，通常可信。反之充滿 emoji 與
「Intelligence Dataset」「Real-World Patterns」者多為合成。

**票數反映熱門度而非品質**。新發布的高品質資料集票數必然偏低，
不應因票數低而略過。

### 覆蓋邊界：Kaggle 上結構性缺席的領域

掃完 18 個方向後，Kaggle 的資料分布有明顯形狀。它擅長**單一機構直出的大型
作業系統資料**（警政、交通、健保、電網）——這類資料因機關為自己營運而產生，
欄位定義嚴謹、量體大、有官方 codebook。

**系統性缺席的三種**：

1. **需跨機構整合的資料**：選舉（各州郡自行公告）、專利引用。整合成本高，
   個人不會做，做了的機構（MEDSL、PatentsView）有自己的平台
2. **隱私敏感的個體資料**：病患臨床紀錄、個人金融交易
3. **需 API 持續抓取的資料**：多站點空氣品質長期監測、即時交通流量

**實務含意**：若某方向搜尋結果稀少或全是合成資料，通常不是搜尋詞的問題，
而是該類資料在 Kaggle 上**結構性地不存在**。此時應直接轉向專門平台，
不要換關鍵字重試。捷運閘門、國際貿易、建築執照三個關鍵字全部回傳空結果，
而它們正是最符合「窄表但單位間有關係」判準的目標型態——因為都是機構內部
營運系統，只提供 API 或需個別申請。

**主題的好壞與該主題在 Kaggle 上的資料品質無關**。空氣品質、共享單車、
顧客流失三個方向的資料結構本應理想，但就是沒有可信版本。不可因主題吸引人
就放寬標準。

### 搜尋策略：發布者檢索比關鍵字有效

主題關鍵字的邊際報酬會快速遞減，但**發布者檢索是另一個維度，且幾乎沒被用過**。

高品質資料集不是隨機分布的，它們聚集在少數認真的發布者手上。找到一個好資料集
就等於找到一個好發布者，其他作品大概率同樣好。`arimancy` 的五個資料集涵蓋
電網、期貨部位、航班氣象，主題毫不相關，但工程標準完全一致。

**標準動作**：

1. 用主題關鍵字找到第一個高品質資料集
2. 立刻用 `search_datasets({user: "<name>", group: "User"})` 檢索該發布者全部作品
3. 若是機構帳號（`organizations/chicago`、`organizations/fda`），整份清單掃過

已驗證值得追的帳號：

- **`arimancy`**（Arimancy LLC）：電網 × 3、CFTC 期貨部位、航班實測氣象。
  全部 CC BY 4.0、附資料字典與洩漏防護說明
- **`organizations/chicago`**、**`organizations/new-york-city`**：市府官方帳號
- **`robikscube`**（Rob Mulla）：航班延誤原始整理版

### 資料集描述有時比資料本身更有價值

候選 I 的描述引用了 DOT OIG 在 2024 年 10 月的稽核，**直接推翻了候選 F 的
核心賣點**（「官方已將延誤分解成五種成因」）。若沒讀到，F 會帶著一個已被
官方否定的假設進入正式分析。

認真的發布者會在「Why this dataset is different」段落說明既有資料的問題，
**那正是免費的文獻回顧**。

## NYC Open Data（Socrata 平台）

- **URL**：https://data.cityofnewyork.us/
- **需登入或申請**：否（匿名可用 API，但有速率限制；註冊取得 app token 可提高上限）
- **取得方式**：**Socrata Open Data API（SODA）**，支援 SoQL 查詢語言
- **我能否自動取得**：**能，且極為順暢**。已實測
- **狀態**：**可用（已於 2026-09-18 實測）**

### API 用法（已驗證可用）

```bash
# 取得資料集 metadata 與完整欄位清單
curl "https://data.cityofnewyork.us/api/views/{dataset_id}.json"

# 聚合查詢：不下載全量即可做篩選檢視
curl "https://data.cityofnewyork.us/resource/{dataset_id}.json?\$select=count(*)"
curl "https://data.cityofnewyork.us/resource/{dataset_id}.json?\$select=col,count(*)%20AS%20n&\$group=col&\$order=n%20desc&\$limit=10"
curl "https://data.cityofnewyork.us/resource/{dataset_id}.json?\$select=min(date_col),max(date_col)"
```

### 踩過的坑

**1. `$group` 的排序欄位**：`$group` 搭配 `count(*)` 時，**不可用 `count_1` 當排序欄位**（會報 `query.soql.no-such-column`），須用 `count(*) AS n` 明確命名別名再 `$order=n desc`。

**2. 列級下載不可用 `$order` + `$offset` 分頁**（2026-09-19 實測，候選 K）

這是取得列級資料時最重要的一條。實測數字：

| 查詢 | 耗時 |
|---|---|
| `$limit=50000` + `$order=unique_key` | **逾時（>300 秒）** |
| `$limit=50000` 無 `$order` | **2.9 秒** |

差距超過 100 倍。原因是排序欄位無索引，Socrata 每一頁都對全表重做排序。
資料集有 365 萬列時，74 頁分頁等同重排 74 次，實務上跑不完。

但**不能單純拿掉 `$order`**——沒有穩定排序，`$offset` 分頁會漏列或重複。

**正確解法：以時間欄位做切片，取代 offset 分頁。**

```python
# 每片是獨立的範圍查詢，不需排序；切片互斥且週延，天然保證不重不漏
where = f"created_date >= '{lo}T00:00:00' and created_date < '{hi}T00:00:00'"
params = {"$select": ",".join(cols), "$where": where, "$limit": "200000"}
```

切片寬度依資料密度決定（候選 K 為每 7 天約 7 萬列）。`$limit` 應設得比
預期切片大小寬鬆，並在程式中檢查是否觸及上限——觸及即代表切片太寬、
資料被截斷。

實測驗證：53 個切片取得 3,655,040 列，與 `count(*)` 完全一致、
`unique_key` 無重複。耗時從「跑不完」降到數分鐘。

**3. App token 不解決效能問題**

Socrata 對匿名請求以 IP 節流，官方聲明帶 token 者不節流。但**節流與上述的
排序問題是兩回事**——候選 K 的瓶頸是 `$order`，加了 token 仍是 2 KB/s，
改用日期切片後才解決。

token 申請：https://evergreen.data.socrata.com/signup
使用方式：`X-App-Token` 標頭（首選）或 `$$app_token` 查詢參數。
token 無 secret 成分、不算認證，僅用於將請求歸屬到特定應用程式。

另有 Secret Token（API Key ID + Secret，走 HTTP Basic Auth），
用於**寫入**資料或讀取私有資料集。讀取公開資料集不需要，**不應設定**，
以免多一份等同帳號密碼的憑證需要保管。

**4. 重複的抓取進程會互相餓死**

實測曾因兩個進程同時抓同一端點，速率被壓到 4 KB/s；殺掉其中一個後
立即恢復 510 KB/s。若速率異常低，先確認沒有殘留的舊進程。

**5. SODA 3.0 的變更**

SODA 3.0（2025 年釋出）**強制要求 token**，且端點由
`/resource/{id}.json` 改為 `/api/v3/{id}/query.json`，並建議改用 POST。
目前 2.1 端點仍可用，但新寫的程式應考慮相容性。

**這個平台的關鍵優勢**：SoQL 聚合查詢讓「篩選用檢視」幾乎零成本——筆數、欄位分布、時間範圍都能在不下載任何資料的情況下取得。相較於 Kaggle 必須先下載才能看內容，這是本質上更好的探索體驗。

**但聚合查詢有其極限**（2026-09-19 修正）：候選 K 的前期數字確實全以聚合查詢取得，未下載任何檔案。然而判斷「生存分析素材是否成立」必須看列級資料——右設限比例、處理時間分布、同機關同類型下的地區差異，聚合查詢都看不出來。實際下載 2025 全年 365 萬列後，才發現右設限僅 1.52%、`due_date` 缺失 99.55%，兩項原始賣點皆不成立。

**教訓**：聚合查詢適合快速篩掉明顯不合格的候選，但**不足以確認一個候選可用**。真正的判斷仍需列級資料。

**同類平台**：Socrata 是許多美國城市與州政府的共用平台（芝加哥、洛杉磯、西雅圖、達拉斯等），**API 語法完全一致**。找到一個城市的用法即可套用到其他城市。

### 搜尋方式（2026-09-18 實測，重要）

**網頁搜尋頁 `https://data.gov.tw/datasets/search?p=1&size=10&s=_score_desc` 無法直接抓取**。該站為 Nuxt SSR，搜尋結果由前端非同步載入，HTML 內的 `__NUXT_DATA__` 只含機關／格式／分類的下拉選單資料，**不含任何搜尋結果**（`href="/dataset/{id}"` 命中數為 0）。

已試過且**失敗**的 API 端點：
```
/api/front/dataset/search      → 404
/api/v1/dataset/search          → 404
/api/dataset/search             → 404
/api/v2/rest/dataset/search     → 200 但報錯 "Expected number, 'search' given"（此端點只吃數字 ID）
/api/v2/rest/dataset?page=&size= → 405
```

**可用的三個管道：**

| 管道 | URL | 內容 |
|---|---|---|
| 單筆 metadata | `/api/v2/rest/dataset/{id}` | 完整詮釋資料，含欄位說明、涵蓋期間、下載 URL |
| 簡易清單 | `https://file.data.gov.tw/event/dataset.csv` | 2.7 MB、29,058 筆。僅 5 欄（機關、名稱、瀏覽數、下載數、評分） |
| **完整中繼資料** | **`https://data.gov.tw/datasets/export/csv`** | **66 MB、53,194 筆、22 欄** |

**`/datasets/export/csv` 是最有用的一個**，22 欄包含：資料集識別碼、名稱、服務分類、檔案格式、**資料下載網址**、編碼格式、**資料集描述**、**主要欄位說明**、提供機關、更新頻率、授權方式、上架日期、**資料量**。

| 策略 | 命中 | 結果 |
|---|---|---|
| 依欄位數排序 | 5,439 筆 ≥25 欄 | **失敗**。前 30 名全是政府預算書表（中央銀行資金流量表 1,201 欄） |

### 已實測的資料集

| 代號 | 名稱 | 格式 | 解析度 | 實測跨度 | 滾動視窗 |
|---|---|---|---|---|---|
| `d006010` | 各機組過去發電量 | JSON | 10 分鐘 | 3 個月 | **是** |
| `d006005` | 過去電力供需資訊 | CSV | 日 | 19 個月 | 否 |
| `d006009` | 各區域間過去電力潮流量 | JSON | 10 分鐘 | 3 個月 | **是** |

### 踩過的坑

**1. 10 分鐘解析度的資料集是滾動視窗，舊資料不保留**

`d006010` 與 `d006009` 上架多年、宣稱每月更新，實際各自只保留約 3 個月
（皆為 2026-02-01 至 2026-04-30）。2026-08-24 與 2026-09-19 兩次抓取**內容完全相同**，
`Last-Modified` 停在 2026-08-24，疑似已停止更新。

日頻的 `d006005` 不是滾動視窗，保有 19 個月。

**實務意涵**：若要採用 10 分鐘資料並累積更長跨度，**必須定期下載存檔**。
下載腳本應**不覆寫既有檔案**，依下載日期另存快照
（見 `scripts/fetch/taipower-region-flow.py`）。

**2. 2026-04-01 在兩個 10 分鐘資料集中都被重複載入整日**（2026-09-19 實測）

| 資料集 | 重複筆數 | 重複日期 | 值是否一致 |
|---|---|---|---|
| `d006010`（L） | 22,032 | 2026-04-01 | 完全相同 |
| `d006009`（L-3） | 576 | 2026-04-01 | 完全相同 |
| `d006005`（L-2，日頻） | 0 | — | — |

兩個不同資料集、同一天、同樣的整日複製型態，指向**共用的產製管線**。
日頻資料集不受影響。

**實務意涵**：處理台電任何 10 分鐘資料前，**先對 2026-04-01 去重**。
不去重會讓該日的系統總出力虛增一倍，在時間序列圖上形成假尖峰。
去重鍵須用（機組或鏈路, 時間戳），不可只用時間戳。

**3. JSON 帶 UTF-8 BOM**

須以 `encoding='utf-8-sig'` 讀取，否則第一個 key 會多出 `﻿`。

**4. 唯一鍵可能不是單一欄位**

`d006010` 的 `UNIT_NAME` 有 151 個值，但 (`UNIT_NAME`, `FUEL_TYPE`) 組合有
**153 個**——`中火` 與 `大潭` 各同時擁有風力與太陽能設施。
**只用機組名當鍵會出錯。**

**5. 欄位名稱的方向不等於實際流向**

`d006009` 的鏈路名稱如「中送北潮流」，實測 **82% 的時間 `P` 為負**，
代表實際流向是北送中。名稱描述的是**量測方向的慣例**，非實際流向。
看到帶方向性的欄位名稱，應先看值的正負分布再決定研究問題。

**6. 零值是結構性的，不是缺失**

`d006010` 全體零值佔 49%，但分燃料別看有明確結構：核能 100% 為零
（2026 年已除役）、輕油 99.9%（尖載備用機組極少啟動）、抽蓄 79%
（離峰充電時出力為零）。**不可當作缺失值處理。**

同理，抽蓄發電的負值為 0，表示此資料**只記錄放電不記錄抽水**，
無法完整分析儲能行為。

## 台灣替代資料的查證結果（2026-09-19）

針對一二梯隊的三個美國候選（I 航班、J 選票、C 健康調查），逐一查證台灣是否
有結構相當的替代資料。**結論：三者皆無可用替代品，且原因各不相同。**

### 候選 I（航班延誤）→ 台灣無逐班歷史資料

| 來源 | 狀態 | 問題 |
|---|---|---|
| 民航局準點率統計 https://www.caa.gov.tw/StatisticsYearMonthFile.aspx?a=1090 | **粒度不足** | 僅**月報**，格式為 XLS/ODS/PDF。涵蓋民國 97 年至 115 年 7 月，但為機場／航空公司層級的月彙總，**非逐班紀錄** |
| 民航局開放資料集 https://www.caa.gov.tw/article.aspx?a=294 | 待驗證 | 未見逐班歷史檔 |
| TDX 運輸資料流通服務 https://tdx.transportdata.tw | **無歷史檔** | 有航空 API，但為**班表（靜態排程）與即時 FIDS**。歷史資料查詢功能（v3.1）主要針對公共運輸，是否涵蓋航空未確認。需註冊取得 Client Id / Secret |
| 政府資料開放平臺「Real-time flight information」 | **即時快照** | 即時航班資訊，無歷史累積 |

**致命差異**：候選 I 的核心是「逐班 × 起降兩端實測氣象 × 航空公司自報延誤原因」
三者對接。台灣端**缺最關鍵的兩項**——沒有逐班的實際起降時刻歷史檔，
也沒有航空公司自報的延誤成因欄位。少了自報成因，「低報稽核」這個研究問題
在台灣**根本無法成立**，不是資料較少的問題，是研究設計不存在。

若要在台灣做航班題，唯一路徑是自行長期爬取 TDX 即時 API 累積歷史，
**這是數月的前置工作**，不適合本專案時程。

### 候選 J（逐張選票）→ 台灣無個體層級選票資料

| 來源 | 最細粒度 | 說明 |
|---|---|---|
| 中選會開放資料 https://data.cec.gov.tw/ | **投票所層級** | 27 個資料類別，含投開票所設置地點、依性別與年齡分組的投票統計 |
| 選舉資料庫 https://db.cec.gov.tw/ | 投票所層級 | 候選人得票數、政黨、選舉區 |
| 政府資料開放平臺 dataset/13119 | 投票所層級 | CSV，政府資料開放授權條款第 1 版，選後 7 日內更新 |

**致命差異**：台灣**不存在**逐張選票紀錄（cast vote record）的公開資料，
最細粒度是**投票所彙總**。這不是取得難度問題，而是制度差異——美國部分州
的選務系統（Dominion、ES&S）會輸出 CVR 且法規要求公開，台灣的開票制度
不產生這種個體層級紀錄。

候選 J 唯一無二的賣點正是「個體層級 × 多重選擇」，而**投票所彙總資料恰恰是
生態謬誤的來源**，不是解方。用台灣資料做這題等於放棄整個研究設計。

反過來說，這強化了 J 的方法論價值：以個體資料檢驗彙總推論的偏誤，
在台灣**做不到**，這正是 J 值得做的理由。

### 候選 C（健康風險行為調查）→ 有結構相當者，但取得受阻

台灣有兩份與 BRFSS 設計相當的調查，**結構上是本次查證中最接近的替代品**：

**1. 國民健康訪問調查（NHIS）** https://nhis.nhri.edu.tw/

- 2001、2005、2009、2013、2017 年（每四年一次，另有 2021 年）
- **多階段分層系統抽樣**：全台 359 鄉鎮市依地理位置與都市化程度分七層，
  層內以 PPS（機率比例）抽樣
- 各縣市抽出率不同，**需以權重調整**才能推估全國值
- **與 BRFSS 的設計高度對應**：分層 + 群集 + 權重三者皆備

**2. 國人健康促進暨健康行為監測調查** https://www.hpa.gov.tw/Pages/List.aspx?nodeid=111

- **明確以美國 BRFSS 為藍本**建立
- 2007 年起，監測 15 歲以上（2012 年前為 18 歲以上）
- 2021 年起納入手機抽樣以改善涵蓋率（BRFSS 亦有同樣演進）
- **資料具縣市代表性**，可做地區分析

**致命傷：兩者皆須經衛生福利資料科學中心申請，且不得下載**

https://dep.mohw.gov.tw/DOS/cp-5119-59201-113.html

- 申請資格限公務機關、學術研究機構、取得當事人書面同意的相關產業。
  研究生**須依附機構**提出，非個人可直接申請
- 須經**審議會審查**
- NHIS 另須檢附 **IRB 核准文件**與研究計畫書
- **須赴 10 處研究分中心的獨立區內現場分析**，僅能攜出**經審查的統計結果**，
  **原始資料不得下載**
- 依「衛生福利統計資料整合應用服務收費標準」**收費，且不退費**

**判定：不可行**。IRB + 審議會 + 現場分析 + 收費，流程以月計，
與本專案時程不相容。這與 CLAUDE.md 將 SRDA 列為最低優先級的理由相同
（需申請、流程慢），且限制更嚴——SRDA 至少可取得檔案，資科中心連下載都不允許。

### 這次查證得到的一般性判斷

**台灣開放資料的粒度天花板通常是「機構彙總」，不是「個體紀錄」。**
三個候選的替代品全部卡在同一點：

| 候選 | 美國端粒度 | 台灣端粒度 |
|---|---|---|
| I | 逐班航班 | 機場／航空公司月彙總 |
| J | 逐張選票 | 投票所彙總 |
| C | 逐人訪問（可下載） | 逐人訪問（**不可下載**） |

個體層級資料在台灣**不是不存在，而是不公開下載**——健保資料庫、NHIS、
健康行為監測皆屬此類，全部走資科中心的現場分析模式。

**對選題的影響**：若堅持用台灣資料，實務上等於接受「彙總層級分析」，
而本專案已有的台灣候選（N 交通事故、L 台電）恰好都是少數提供**列級**
下載的例外。這也解釋了為什麼 N 在台灣候選中受益者最強——
**它是罕見的「個體層級 + 可直接下載 + 政策可執行」交集**。
