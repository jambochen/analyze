# 依狀態調整的勝率

腳本：`scripts/state_adjusted_probs.py`。共用 module：`scripts/arena_batches.py`（`player_sample_rd`）、`scripts/likelihood.py`（`fit`、`dyad_se`）。表在 `outputs/tables/state_adjusted_probs_*.csv`，圖在 `outputs/figures/state_adjusted_probs_curve.png`。規格見 `docs/methods.md`「依狀態調整的勝率」。本文件只寫定性結論，數值一律見對應的輸出檔。

## 問題

玩家排完隊、看到對手之後，系統給的期望勝率能否依雙方剛才的對局修正得更準？電競玩家看得到對手的近期戰績，所以自身與對手的近況都是可用的資訊。這是預測交付物：修正後的勝、和、負機率，與「再開一局，預期比系統的期望差多少」。預測只需要預測力，不需要因果的識別，所以變數由樣本外表現決定，不由前局效果是否顯著決定。

## 資料與做法

- 2014 年 arena 的玩家局，取同一場錦標賽內有上一局者；上半年估計，下半年評估。各速度類別、上一局結果的列數、玩家數與對手在本場沒有上一局的比例見 `state_adjusted_probs_sample.csv`
- 近況只用上一局：比上一局更早的對局幾乎不再改善預測（`docs/results/history-depth.md`）
- 模型為有序 logistic，主基準的線性預測式與和局帶寬作 offset。依序加入四步，每一步都要下半年的對數分數改善、且差值以 dyadic sandwich 估得的 95% 區間不含 0 才保留，下一步以目前保留的模型為比較基準：
  1. arena 的整體校正：線性預測式的平移與和局帶寬的縮放。主基準以全站對局估計，arena 的玩家與大廳不同
  2. 自身的上一局結果（勝、和、負），以剛輸為參照
  3. 自身上一局等級分的變動 $\Delta r$：本局與上一局表頭的對局前等級分之差，不用 `RatingDiff`
  4. 對手的近況：取自身已保留的項，雙方共用係數、以「自身減對手」進入線性預測式，等於依近況調整雙方的等級分。對手在本場沒有上一局時以一個指標變數吸收
- 第四步只有共用係數的形式。每局以雙方的視角各出現一次、結果互為鏡像，對手的近況另給一組係數時，最大概似估計因對稱必落在共用係數上；「對手的近況與自身的近況是否等量反向」在這個設計下無從檢驗
- 參照模型：LightGBM、XGBoost 與 MLP，輸入相同：雙方等級分與 RD、執子顏色、主基準的線性預測式與和局帶寬、自身前三局結果與 $\Delta r$、對手的上一局結果與 $\Delta r$、場內局數，全為對局前的資訊。資訊量涵蓋有序模型的輸入，差異只來自模型。MLP 的輸出層經與有序 logistic 相同的累積 logit 得到機率。early stopping 只用上半年的 6 月，下半年不參與任何選擇
- 評估：對數分數、ranked probability score，全部、新手、老手三組分開報告（`state_adjusted_probs_prediction.csv`）；依上一局結果分色的校準曲線（`state_adjusted_probs_curve.png`）

## 結論

### arena 的整體校正在三個速度類別都不保留

- 以上半年估得的平移與和局帶寬，套到下半年反而不如主基準本身（`state_adjusted_probs_steps.csv`）。arena 的整體偏差在半年之間不穩定，主基準不需要為 arena 另作整體調整
- 主基準的係數以含下半年的全年全站對局估計，評估時對它略為有利；各候選模型共用同一個 offset，這一點不偏袒近況項

### 自身的上一局結果在三個速度類別都保留；$\Delta r$ 只在 Blitz 與 Classical 保留

- 加入上一局結果，三個速度類別的下半年對數分數都改善，區間不含 0
- 再加入 $\Delta r$，Blitz 與 Classical 保留，Bullet 不保留。Classical 的區間上界接近 0，樣本最小
- 方向與 `docs/results/rating-filter.md` 一致：剛贏之後好於系統的期望；給定上一局結果，上一局等級分升越多下一局越好，即等級分調得不夠（`state_adjusted_probs_coef.csv`）

### 對手的近況在三個速度類別都保留，改善大於自身的近況

- 加入對手的近況後，下半年的對數分數在三個速度類別都再改善，區間不含 0，增量大於自身近況兩步的合計。共用係數使每一項同時用上雙方的資訊，且多了對手在本場沒有上一局的指標
- 對手在本場沒有上一局時，Bullet 的自身表現明顯好於期望；Blitz 方向相同、Classical 不明顯。對手處於本場第一局，與 `docs/results/history-depth.md` 的「本場第一局較差」是同一個型態，屬看過結果才形成的型態
- 改善的幅度相對於對數分數本身仍小：近況修正的是期望得分的小幅平移，不改變勝負的大致判斷

### 「再開一局」的差距取決於雙方近況之差

- 修正後與主基準的期望得分之差，以主基準的斜率換算成等級分，依速度類別、雙方的上一局結果、新手與否列在 `state_adjusted_probs_gap.csv`
- 雙方上一局結果相同時，結果項互相抵銷；自己剛贏、對手剛輸時修正為高於系統的期望，反之低於。對手處於本場第一局時修正為高於期望
- 換算成等級分，新手的修正幅度大於老手

### 機器學習與深度學習模型不構成預測上限

- LightGBM、XGBoost 與 MLP 的下半年對數分數，在全部與老手組都不如有序模型；只在 Bullet 與 Blitz 的新手組較好，Bullet 的 MLP 區間含 0；Classical 的新手組也不如有序模型（`state_adjusted_probs_prediction.csv`）
- 老手組較差，表示它們從上半年 arena 重新學到的等級分與勝率的對應，套到下半年不如以全站對局估計的主基準穩定。資訊量相同時，彈性較大的模型沒有換到樣本外的改善；「有序模型還剩多少可改善」因此無法由它們給出上界
- 新手組的差距在樹模型與神經網路都出現，不是單一模型的偶然，表示新手的勝率還有主基準與近況項沒有抓到的結構。這是看過結果才發現的型態，不回頭加入有序模型的候選項；登記為事後型態，以前瞻資料檢驗

### 校準曲線

- 修正後，剛贏與剛輸的曲線大致重合，上一局結果造成的分離被吸收；Bullet 的中段剛輸略高於、剛贏略低於預測
- 修正後的曲線仍隨預測的期望得分略為上升：強方的實際得分高於預測，弱方低於預測。這是 arena 上的斜率偏差，整體校正只含平移與和局帶寬，不含斜率；斜率不在事先寫定的候選項中，寫成限制
- Blitz 中預測得分最高的一格，剛輸之後的實際得分明顯低於修正後的預測

## 對後續分析的意涵

- **demo**：輸入雙方等級分、RD 與各自的上一局結果，Blitz 與 Classical 另需雙方上一局等級分的變動，對手在本場的第一局另標記；係數取 `state_adjusted_probs_coef.csv`，即上半年估得的模型
- **前瞻驗證**：登記的檢驗量為本模型（各速度類別保留的項與上半年估得的係數）對主基準的樣本外對數分數差；新手組的彈性模型差距與本場第一局一併登記為事後型態

## 限制

- 樣本只限 arena 內有上一局的局；大廳對局待 API 的 `source` 取得後才能納入
- 主基準的係數含下半年的資料，見上
- 修正後仍有 arena 上的斜率偏差，見上
- 對手的近況在 2014 年下半年之前未列入候選，加入時自身近況各步的結果已看過；結論的效力以前瞻驗證為準
- Blitz 的上上局有小幅增量但不加入，見 `docs/results/history-depth.md`
- 本模型的樣本限自身在本場有上一局的局，自身本場第一局的勝率由主基準給出
