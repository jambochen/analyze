## 一、美國航班延誤的低報稽核

**已實測** · https://www.kaggle.com/datasets/arimancy/observed-weather-us-flights

**研究問題**：以實際觀測氣象為基準，哪些航空公司、機場與航線系統性地
少報天氣延誤？低報程度能否量化排序，作為監理查核的優先順序？

| | |
|---|---|
| 內容 | 每一班美國國內航班，接上起降兩端機場在正確時刻的**實際觀測氣象** |
| 上游 | US DOT BTS 準點紀錄 + NOAA ISD 氣象 + OurAirports 座標 |
| 筆數 | 4,280 萬筆航班，2019-01 至 2025-07 |
| 規模 | 完整版 6.1 GB；24 個月入門檔 1,406 萬列、1.1 GB，schema 相同 |

**為什麼推薦這個**

美國運輸部監察長（OIG）已經認定航空公司自報的延誤成因不可信，
但沒有提出替代的查核方法。而這份資料的作者做了一張**機場對 NOAA
氣象測站的對照表**，他說這「不存在於任何維護中的公開資料」。

換句話說：**掌握資料的航空公司沒有動機自己做這個分析**，
而監理單位需要但手上沒有工具。這是四個問題裡第三問答得最漂亮的一個。

**資料結構的亮點**

欄位用前綴分三類，實測確認：

```
wx        106 欄   航班資訊截止點「之前」的氣象，可安全使用
oracle     54 欄   航班自身事件時刻的氣象，用於預測即洩漏
reported    5 欄   航空公司自報的延誤成因，刻意保留但標明不可信
其他        46 欄   航班識別、日曆、壅塞度、前段航班
```

**等於把資料洩漏的風險寫進欄位命名裡**，這在公開資料集裡很少見，
對我們是實質的保護——只要不碰 `oracle_` 前綴就不會出事。

**關鍵賣點的實測**（入門檔，僅供篩選非分析結果）

```
起點天氣    班次          平均抵達延誤   取消率
VFR      11,910,145        6.02 分      1.12%
MVFR      1,293,044        8.52 分      1.78%
IFR         492,421       15.76 分      3.26%
LIFR        344,515       17.83 分      3.52%
```

VFR 到 LIFR 是天氣從好到壞（目視飛行到儀器飛行）。延誤與取消率
**單調上升**，代表氣象與延誤的關係真實存在，那麼「實際氣象 vs
自我回報」的落差就算得出來。

**可以做的方法**：低報程度的量化與排序、實測氣象的劑量反應、
用機尾號串接當日航段做延誤傳播、起降機場構成有向網路。

**代價**：完整版 6.1 GB（可先用入門檔）；`oracle_` 欄位絕對不能進
預測模型；結果變數強右偏。

**台灣做不了這題**——不是資料難拿，是台灣**沒有「航空公司自報延誤
成因」這個欄位**。民航局只有月彙總的 XLS/PDF，TDX 只有班表與即時資訊。
少了自報這個對照基準，低報稽核這個研究設計整個不存在。

## 二、美國 PJM 電網的負載與氣象

**尚未實測**（欄位清單已確認） ·
https://www.kaggle.com/datasets/arimancy/pjm-hourly-demand-weather

**研究問題**：電力需求中有多少可以由氣象解釋、多少屬於資料中心帶來的
結構性成長？冬夏雙峰的氣溫反應函數形狀差異為何？

| | |
|---|---|
| 上游 | EIA-930 經 PUDL 清理 + EIA API + Open-Meteo ERA5 + Census 人口權重 |
| 筆數 | 97,850 小時（2015-07 至 2026-08，11 年），**UTC 軸上無缺漏小時** |
| 規模 | 54 MB |
| 授權 | CC BY 4.0 |

這個我一開始排得很後面，理由是「負載預測的使用者是調度單位，
他們資訊遠多於公開資料」。但後來覺得**這樣問是問錯了**——
負載預測不是這份資料唯一能做的題目，而且是最不該做的那個。

它真正撐得起的是**氣象效應與資料中心結構性成長的分離**。
PJM 作為市場營運者，對「新增負載有多少來自資料中心」做出公開歸因，
會直接牽動成本分攤與併網排隊的爭議——**沒有動機自己做**。
受益者是聯邦能源管理委員會（FERC）與各州監理單位，不是調度單位。
這個結構其實跟第一個候選是同一類。

**資料工程品質是四個裡面最高的**：所有插補與初步值都有旗標
（`demand_source`、`weather_is_preliminary`、`temp_is_missing`、
`is_dst_transition_day`），連夏令時轉換日都標出來了。
跨年比較需要的條件是逐項備妥的，不用自己推敲哪些年份可比。

**可以做的方法**：氣溫的非線性反應（U 形，冬夏雙峰）、趨勢與季節分解、
多重季節性時間序列（日內／週內／年度三重週期）、極端事件分析
（2022 年 Winter Storm Elliott 與 2025 年 1 月寒潮都在範圍內）、
變點偵測（資料中心負載成長是否有明確起點）。

**限制**：第三問靠的是立場而不是資料獨佔——誰都能下載做同樣分析；
**沒有空間維度**（是全區總量，不是分區資料）；ERA5 是再分析模式估計
不是測站觀測；所有需求特徵至少要落後 24 小時，違反會做出看似優異
實則無效的結果。

## 四、台灣電網的機組發電行為（唯一的台灣題目）

**已實測** · data.gov.tw → 台灣電力公司開放資料

**研究問題**：不同燃料別機組的日內出力型態如何分群？太陽能與風力的
間歇性由哪些機組承接？再生能源滲透率上升時，傳統機組的調度模式
如何改變？

這是三份資料，我都跑過了：

| | 機組發電量 | 供需資訊 | 區域潮流 |
|---|---|---|---|
| 資料集 | `d006010` | `d006005` | `d006009` |
| 筆數 | 1,960,848（去重後） | 577 | 51,264（去重後） |
| 解析度 | 10 分鐘 | 日 | 10 分鐘 |
| 跨度 | **3 個月** | 19 個月 | **3 個月** |
| 維度 | 151 機組 × 10 燃料別 | 6 個可用系統指標 | 4 條鏈路，2 條有變異 |

取得方式：直接下載 JSON，無需 API key。
**注意有 UTF-8 BOM，要用 `encoding='utf-8-sig'` 讀。**

**這份資料最有意思的地方是「窄表但結構可衍生」**

機組發電量那份只有 4 欄（燃料別、機組名、時間戳、淨發電量），
但結構撐得起很多東西：

- **泛函資料分析**：每個機組每天是一條 144 點的日出力曲線，
  151 機組 × 89 天 ≈ 13,400 條曲線，可做曲線分群與主成分分析
- **平衡面板**：機組 × 時間，混合效應模型（機組為隨機效果、
  燃料別為固定效果）
- **組成資料**：每個時點的燃料別發電佔比是一個組成向量
- **調度順序推論**：由各機組的啟停時序反推實際的經濟調度順位

資料品質實測下來相當紮實：四欄缺失率皆 0%、12,816 個時間戳零缺漏、
面板完全平衡。行為也通過電力系統常識檢驗——太陽能日中單峰、
抽蓄雙峰放電、水力跟隨晚尖峰、春節出現低點。

**但我還是把它排在最後，有幾個實測發現的問題**

**一、跨度只有 3 個月，而且是滾動視窗。**
資料起訖 2026-02-01 至 04-30，**不含夏季尖峰**——而夏季尖峰正是台灣
電力系統最值得研究的時段。更麻煩的是舊資料不保留在同一端點，
要累積更長期間得定期下載存檔，這對學期報告的時程不可行。

**二、內容有大片空白。**

- **核能全期為零**（核三 #1、#2，已除役）
- **輕油 99.9% 為零**
- **抽蓄發電負值為 0**——只記錄放電不記錄抽水，無法完整分析儲能

10 個燃料別裡有 2 個實際上沒東西可研究。

**三、供需資訊那份的欄位數會誤導人。**
它標示 71 欄，但其中 64 欄是**尖峰時刻的快照**而非全日發電量
（所以太陽能有 117 天為零），另有 11 個機組欄位全期為零。
**真正可用的系統層級指標只有 6 欄。** 而且樣本只有 577 列，
備轉容量率橘燈 0 天、黃燈僅 35 天，極端情境的事件數太少。

**四、區域潮流那份，我原本的賣點被自己的實測推翻了。**

我本來以為 `P` 欄可以為負代表反向潮流，負值本身就是研究對象
（何時北部反送中部）。實測結果：

```
鏈路          平均 MW    負值率    標準差
中送北潮流    −1,167     82.19%     1,236
南送中潮流    −1,331     81.86%     1,286
南送東潮流       +10     44.89%        53
中送東潮流      +286      0%           53
```

**負值是常態不是稀有事件。** 欄位名稱描述的是量測方向的慣例，
不是實際流向——「中送北」絕大多數時間實際上是北送中。
我原本的問題問錯方向了，真正罕見的是正值。

另外東部那兩條的變異極小（標準差 53，相較主幹線的 1,200 以上），
其中 `中送東潮流` 從未出現負值、近乎常數——**實際有變異可研究的
只有兩條主幹線**。

**五、缺氣象與電價。**
太陽能與風力的出力分析如果沒有日照與風速資料，解釋力受限。
要接中央氣象署的資料，那是另一個取得流程。

**順帶一個實測發現**：2026-04-01 這天在兩個不同的 10 分鐘資料集裡
都有整日重複（機組發電量 22,032 筆、區域潮流 576 筆，值完全相同），
但日頻的供需資訊沒有。這表示是**台電 10 分鐘解析度資料集共用產製管線
的系統性問題**，不是個別資料的瑕疵。去重是可預期的固定前處理步驟。

**受益者問題**：台電調度中心掌握即時資料，資訊遠多於我們。
美國那個 PJM 的候選之所以還有路走，是因為 FERC 與州監理單位跟
市場營運者是對立的第三方，需要獨立歸因；台灣的能源署與台電關係不同，
比較難找到對應的角色。

## 小結

| | 候選 | 第三問（我們有什麼他們拿不到） | 狀態 |

**我自己傾向第一個。** 它是唯一四個問題都答得出來的，而且研究問題
單一清楚——最後交付的東西就是一份監理查核的優先清單。

**第二個（PJM 電網）我覺得值得考慮。** 它跟第一個其實是同一種結構：
掌握資料的一方（市場營運者）沒有動機自己做這個歸因，而監理單位需要。
資料工程品質也是最高的。我還沒實測，要選的話我先跑一輪。

**台灣題目目前只剩電網這一個，但它的問題比較實際**——只有 3 個月、
不含夏季尖峰，而且是滾動視窗。如果大家希望做台灣題目，
我可以再找找別的方向，但要先講清楚：台灣開放資料的粒度天花板通常是
「機構彙總」而不是「個體紀錄」，這是我查下來最常撞到的牆。

歡迎提意見，尤其如果有人覺得我第三問這個標準訂得太嚴。
