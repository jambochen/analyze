# 我這邊的選題建議

前一份講了四個提議資料集為什麼我不建議用，這份講我找到的替代方案。

五個候選，我依「值不值得做」排序。每個都附了篩選檢視的結果，
腳本放 gist（`nb_proposals.py`，以 `# %%` 分格，可轉 notebook）。
標「已實測」的是我實際下載跑過的。

---

## 我的判斷標準

看資料的時候我主要問這四件事，排序也是照這個來的：

1. **誰會用這個結果？**
2. **他們手上是不是已經有更好的資料？**
3. **我們有什麼是他們拿不到的？**
4. **這份資料的不同時期，裝的是同一群東西嗎？**

第三個最關鍵。如果資料的主人自己就能做這個分析、而且做得比我們好，
那報告就沒有存在理由——房價就是卡在這裡。

第四個是查 AI 薪資那份資料時學到的，前一份文件有寫。

另外課程要求報告最後要有**預測**或**具體建議**，兩個有一個就好。

## 一、美國航班延誤的低報稽核（推薦）

**已實測** · https://www.kaggle.com/datasets/arimancy/observed-weather-us-flights

**研究問題**：以實際觀測氣象為基準，哪些航空公司、機場與航線系統性地
少報天氣延誤？低報程度能否量化排序，作為監理查核的優先順序？

| | |
|---|---|
| 內容 | 每一班美國國內航班，接上起降兩端機場在正確時刻的**實際觀測氣象** |
| 上游 | US DOT BTS 準點紀錄 + NOAA ISD 氣象 + OurAirports 座標 |
| 筆數 | 4,280 萬筆航班，2019-01 至 2025-07 |
| 規模 | 完整版 6.1 GB；24 個月入門檔 1,406 萬列、1.1 GB，schema 相同 |
| 授權 | CC BY 4.0，上游 BTS 與 NOAA 為美國政府作品 |

**為什麼推薦這個**

美國運輸部監察長（OIG）已經認定航空公司自報的延誤成因不可信，
但沒有提出替代的查核方法。而這份資料的作者做了一張**機場對 NOAA
氣象測站的對照表**，他說這「不存在於任何維護中的公開資料」。

換句話說：**掌握資料的航空公司沒有動機自己做這個分析**，
而監理單位需要但手上沒有工具。這是四個問題裡第三問答得最漂亮的一個。

**資料結構的亮點**

欄位用前綴分三類，實測確認：

```
wx        106 欄   航班資訊截止點「之前」的氣象，可安全使用
oracle     54 欄   航班自身事件時刻的氣象，用於預測即洩漏
reported    5 欄   航空公司自報的延誤成因，刻意保留但標明不可信
其他        46 欄   航班識別、日曆、壅塞度、前段航班
```

**等於把資料洩漏的風險寫進欄位命名裡**，這在公開資料集裡很少見，
對我們是實質的保護——只要不碰 `oracle_` 前綴就不會出事。

**關鍵賣點的實測**（入門檔，僅供篩選非分析結果）

```
起點天氣    班次          平均抵達延誤   取消率
VFR      11,910,145        6.02 分      1.12%
MVFR      1,293,044        8.52 分      1.78%
IFR         492,421       15.76 分      3.26%
LIFR        344,515       17.83 分      3.52%
```

VFR 到 LIFR 是天氣從好到壞（目視飛行到儀器飛行）。延誤與取消率
**單調上升**，代表氣象與延誤的關係真實存在，那麼「實際氣象 vs
自我回報」的落差就算得出來。

**可以做的方法**：低報程度的量化與排序、實測氣象的劑量反應、
用機尾號串接當日航段做延誤傳播、起降機場構成有向網路。

**代價**：完整版 6.1 GB（可先用入門檔）；`oracle_` 欄位絕對不能進
預測模型；結果變數強右偏。

**台灣做不了這題**——不是資料難拿，是台灣**沒有「航空公司自報延誤
成因」這個欄位**。民航局只有月彙總的 XLS/PDF，TDX 只有班表與即時資訊。
少了自報這個對照基準，低報稽核這個研究設計整個不存在。

## 二、2020 美國大選的逐張選票

**已實測** · https://dataverse.harvard.edu/dataset.xhtml?persistentId=doi:10.7910/DVN/PQQ3KV

**研究問題**：選民在同一張選票上跨層級的投票組合呈現哪些型態？
分裂投票的比例與結構為何？能不能用個體資料檢驗過去用郡層級彙總資料
做的推論有多少偏誤？

| | |
|---|---|
| 發布者 | MIT Election Data and Science Lab (MEDSL) |
| 論文背書 | Nature *Scientific Data* (2024) |
| 筆數 | 166,470,734 列，4,270 萬名選民、20 州、逾 2,200 位候選人 |
| 時間 | 2020 年大選，單一時點 |
| 授權 | CC0 |

**實測結果是五個裡面最乾淨的**：列數與論文宣稱**差異 0**。

分裂投票的結構也確認真實可觀測：

```
搖擺州可比對選票   8,570,000 張
明確反向分裂投票     139,000 張（1.62%）
```

「明確反向」是指總統投民主黨但下游全投共和黨，或反過來。

**這份資料的獨特之處**是「個體層級 × 多重選擇」——同一個人在同一張
選票上的多個選擇都在資料裡。這種結構我在其他候選都沒看到。

**可以做的方法**：潛在類別分析或對應分析萃取投票型態、選民巢狀於
選區郡州的多層次模型、跨層級選擇的對數線性模型、生態謬誤的正面檢驗。

**主要問題**：這是選舉研究社群自己發布的資料，CC0 誰都能下載，
MEDSL 已經自己發過 Nature 子刊論文。**第三問答不出來**——
我們沒有他們拿不到的東西。

其他限制：`precinct` 欄缺失 28%（多層次模型第二層只能退到郡）、
州長選舉只有 3 州、無時間維度、20 州非隨機（不能宣稱代表全美）、
政治主題論述要嚴守中立。

**有意思的是台灣做不了這題反而是它的論據**：台灣最細的粒度是投票所
彙總，不存在逐張選票紀錄，這是制度差異不是取得難度。
而投票所彙總正是生態謬誤的來源，不是解方。

## 三、台灣道路交通事故

**尚未實測**（欄位清單與下載路徑已確認） ·
data.gov.tw → 內政部警政署

**研究問題**：控制道路環境、天候、光線與時間後，哪些當事者特徵
（年齡、性別、車種、保護裝備、飲酒、手機使用）對傷亡程度的影響最大？
肇事逃逸的決定因子是什麼？

| | |
|---|---|
| 取得 | 直接下載 CSV，**無需申請** |
| 筆數 | A1 類（死亡）2,587 列；A2 類（受傷）單月 80,620 列，推估年約 100 萬列 |
| 欄位 | **51 欄，而且已經完全解碼**——直接是「雨」「市區道路」這種中文值 |
| 授權 | 政府資料開放授權條款 |

**這是台灣資料裡受益者最明確的一個**——道安會與地方交通局，
而且保護裝備、速限、路口設計的邊際效果都是可以直接操作的建議。

**結構上的優勢**：有經緯度可以做空間統計；而且**當事者巢狀於事故**
是天然的兩層結構——同一場事故的當事者共享環境條件，違反獨立性假設，
**必須用多層次模型處理**。這點讓它在方法上優於一般的事故資料集
（那些通常只有事故層級，沒有當事者層級）。

**可以做的方法**：次序邏輯斯迴歸（傷亡程度是序位）、多層次模型、
空間熱點偵測、保護裝備 × 車種等交互項、道路環境類別變數的多重對應分析。

**限制**：A2 類分散在 9 個 ZIP 要寫腳本串接；「即時」資料只涵蓋當年度，
要做多年得確認歷年版本；**沒有分母**（有事故數但沒有車流量，
算不出事故率，可能要接交通部的交通量調查）；讀檔時 CSV 末尾有兩列
中繼資訊要排除，編碼是 UTF-8 with BOM。

## 四、美國成人健康風險行為（BRFSS）

**已實測** · https://www.kaggle.com/datasets/cdc/behavioral-risk-factor-surveillance-system

**研究問題**：控制個人社經與人口特徵後，各州在健康風險行為
（吸菸、身體活動不足、預防服務使用率）上的差距有多大？

| | |
|---|---|
| 原始出處 | CDC 行為風險因子監測系統年度資料 |
| 筆數 | 每年逾 40 萬份成人訪問，2011–2015 共 5 年，解壓約 2.9 GB |
| 授權 | CC0 |

**這是五個裡面唯一能正當做複雜抽樣加權估計的資料。** 實測確認：

```
七個複雜抽樣設計變數（2015 年 441,456 列）
  _STSTR, _PSU, _LLCPWT, _STRWT, _RAWRAKE, _WT2RAKE, _DUALUSE
  缺失率最高 0.01%

分層數 1,306，單一觀測層 0 個
```

單一觀測層是 0 這點很重要——只要有任何一個分層裡只有一個觀測值，
變異數估計就會失效。

**可以做的方法**：分層 + 群集 + 權重的加權估計、州為第二層的多層次
模型、無反應機制分析、高維類別變數的變數選擇、跨 5 年趨勢。

**這份有個坑，我覺得滿值得提的**：

```
_HCVU651（65 歲以下健保覆蓋）的值分布
  1.0  →  252,542
  9.0  →  159,253    ← 碼 9 = 不知道／拒答
  2.0  →   29,661

null_count = 0
```

它把「不知道／拒答」編成**碼 9，是有效整數不是 null**。
`null_count` 回報 0，看起來完全沒缺失，實際上這一欄 36% 是無效回答。
直接拿去算平均，會得到一個看起來很合理的錯數字。

**主要問題**：BRFSS 公開很多年、文獻極多，**同樣沒有資訊優勢**。
另外轉檔保真度有個未解的落差——吸菸率我實測 16.72%，
CDC 官方公布 17.5%，差 0.8 個百分點還沒釐清。資料也停在 2015。

共同欄位只有 158 欄，其中 59 欄缺失率 ≥70%（那些是分州選作的模組，
缺失跨州系統性不隨機）。

**台灣有結構相當的**（國健署的健康行為監測、國衛院的 NHIS，
分層+群集+權重三者皆備），但**必須經衛福部資科中心申請**：
要依附學術機構、經審議會審查、赴研究分中心現場分析、
原始資料不得下載。流程以月計，跟我們的時程不相容。

## 五、美國 PJM 電網的負載與氣象

**尚未實測**（欄位清單已確認） ·
https://www.kaggle.com/datasets/arimancy/pjm-hourly-demand-weather

**研究問題**：電力需求中有多少可以由氣象解釋、多少屬於資料中心帶來的
結構性成長？冬夏雙峰的氣溫反應函數形狀差異為何？

| | |
|---|---|
| 上游 | EIA-930 經 PUDL 清理 + EIA API + Open-Meteo ERA5 + Census 人口權重 |
| 筆數 | 97,850 小時（2015-07 至 2026-08，11 年），**UTC 軸上無缺漏小時** |
| 規模 | 54 MB |
| 授權 | CC BY 4.0 |

這個我一開始排得很後面，理由是「負載預測的使用者是調度單位，
他們資訊遠多於公開資料」。但後來覺得**這樣問是問錯了**——
負載預測不是這份資料唯一能做的題目，而且是最不該做的那個。

它真正撐得起的是**氣象效應與資料中心結構性成長的分離**。
PJM 作為市場營運者，對「新增負載有多少來自資料中心」做出公開歸因，
會直接牽動成本分攤與併網排隊的爭議——**沒有動機自己做**。
受益者是聯邦能源管理委員會（FERC）與各州監理單位，不是調度單位。
這個結構其實跟第一個候選是同一類。

**資料品質是五個裡面最高的**：所有插補與初步值都有旗標
（`demand_source`、`weather_is_preliminary`、`temp_is_missing`、
`is_dst_transition_day`），連夏令時轉換日都標出來了。
跨年比較需要的條件是逐項備妥的，不用自己推敲哪些年份可比。

**可以做的方法**：氣溫的非線性反應（U 形，冬夏雙峰）、趨勢與季節分解、
多重季節性時間序列（日內／週內／年度三重週期）、極端事件分析
（2022 年 Winter Storm Elliott 與 2025 年 1 月寒潮都在範圍內）、
變點偵測（資料中心負載成長是否有明確起點）。

**限制**：第三問靠的是立場而不是資料獨佔——誰都能下載做同樣分析；
**沒有空間維度**（是全區總量，不是分區資料）；ERA5 是再分析模式估計
不是測站觀測；所有需求特徵至少要落後 24 小時，違反會做出看似優異
實則無效的結果。
