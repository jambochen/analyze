## 結果變數的建模

結果變數分敘述統計量與模型參數的估計，見 `design.md`。**下表的方法屬前者**——
三個比例的邊際分布與其建模。公司的主效應由二元模型與 simplex 的 Poisson
模型產出，見「多類別歸因的完整處理」。

| 方法 | 在本題能回答什麼 | 筆記 |
|---|---|---|
| logistic 迴歸 | Y1 的主力，亦為 two-part model 中 binary part 的模型 | `多變量分析/logistic-regression` |
| one-inflated 兩部模型 | **已採用**。Y2 的 1.0 是二元決策的結果，兩部的公司主效應可方向相反。兩部與 two-part model 的 binary part、conditional part 對應，是同一結構在單一欄位上的特例 | — |
| 分位數迴歸 | Y2 的尖峰使均值失真，分位數效應可能更貼近「掛多少比例」 | — |
| 零膨脹 / hurdle | 天氣分鐘數的零膨脹；與兩部模型的差別在零的生成機制假設 | — |
| 有序 logit / probit | 把 Y2 離散成檔位（全掛、大部分、一半、小部分），避開端點的分布問題。係數解讀為「往更高檔位移動的勝算」，對監理單位比連續比例直觀 | — |
| 廣義有序 / 部分比例勝算 | **one-inflated 的自然推廣**：後者只看「1.0 vs 其他」一個切點，此法同時看所有切點。**比例勝算假設的違反本身是證據**——某公司只在特定切點異常，即為公司 × 切點交互作用的線索 | — |
| 組合資料分析（compositional） | 四個成因欄位的分鐘數本質是 compositional data，落在 simplex 上。目前逐欄看比例忽略了這個約束 | — |
| 廣義加法模型 | 氣象與歸因的關係未必線性（能見度、雲冪尤其可疑），可先用來檢查函數形式 | — |
| 單調迴歸 | 「天氣越差越該歸因天氣」是可施加的形狀約束，違反處即為可疑訊號 | — |

### 有序解釋變數的設定

`wx_*_flight_category_ordinal`（VFR < MVFR < IFR < LIFR）目前**當連續變數放入**，
隱含「每一級的效果等距」。此假設幾乎確定不成立——IFR 惡化到 LIFR 對申報行為的
影響應遠大於 VFR 到 MVFR。變數只有四級，改為 dummy 的成本極低（多兩個參數），
且移除一個不必要的假設。**屬設定正確性問題，須實測確認公司的主效應是否因此改變。**

### 計數與堆積

申報分鐘數是整數，目前只用於構造比例，未直接建模。

| 方法 | 在本題能回答什麼 |
|---|---|
| Poisson / 負二項 | 直接建模天氣分鐘數而非比例；負二項處理過度離散 |
| 零膨脹計數 / hurdle 計數 | 上表的零膨脹寫在連續脈絡下，計數版本的零生成機制不同 |
| **堆積模型（heaping）** | 人工填報會把分鐘數湊整到 5、10、15、30 的倍數。**湊整程度本身即申報品質指標**，且人工與系統自動填報的湊整型態不同，正可對應混合模型中「預設值成分」的解釋。與下方 Benford 類檢定同一思路，但能估出各公司的湊整傾向而非僅做檢定 |
| 過度離散檢定 | 決定 Poisson 或負二項 |

### 多類別歸因的完整處理

「延誤記到哪一欄」是五類選擇。**此節是 conditional part 的主體**，
敘述統計量 Y3 只取其中兩類的比值，不承擔識別。

**已採用多項 logit**，以 Poisson 對數線性的等價形式求解，理由與實作限制見
`decisions.md`。係數在雙重基準下可直接解讀，不需換算邊際效應。

成因之間的比較即這組係數的 contrast：weather 減 NAS 對應敘述統計量 Y3 的
問題，換一個對比向量即可問 weather 對 late-aircraft，不必另立結果變數。

其餘選項與現況的關係：

| 方法 | 在本題能回答什麼 |
|---|---|
| 巢狀 logit | 決策可能是階層的：先定「是否免責事由」（weather + NAS vs carrier + late-aircraft），再定哪一個。比扁平多項更貼近實際決策結構。**現行扁平設定已能分辨「集中導向單一事由」與「整體遠離可歸責」兩種型態**，巢狀的增量在於把後者正式化為第一層的係數 |
| 有序模型（按免責程度） | 若接受 weather > NAS > late-aircraft > carrier 的免責排序，則歸因是有序結果，比多項精簡。**此排序是推論而非 BTS 官方定義，須先辯護** |
| 卡方適合度 | 各公司的成因分配是否來自同一多項分布。多項 logit 已給出帶區間的係數，此檢定的增量有限 |

### 二元資料的小樣本問題

| 方法 | 在本題能回答什麼 |
|---|---|
| Firth 懲罰似然 | 樣本少的公司 × 機場單位可能 complete separation，係數發散。清單要附區間就必須處理。**simplex 的 Poisson separation 不需要它**，理由見 `decisions.md` |
| 稀有事件 logit（King-Zeng） | Y1 的陽性比例不高，小單位內更稀 |
| 條件 logit | 概念上正確的固定效應處理。`ConditionalLogit` 的實作在本資料上不可用（見 `decisions.md`），但那是實作限制，不是方法本身的問題 |

## 列聯表與 GLM 框架

本題的資料結構本質是一張高維列聯表：**公司 × 機場 × 月 × 天氣等級 × 歸因類別**。
前四維是分層，最後一維是結果。現行的 within transformation 就是在這張表裡做條件
比較，只是以迴歸的形式表達。

**對數線性模型與多項 logit 等價**，故此節與「多類別歸因的完整處理」不是兩套
方法，而是同一件事的兩種表達。可用列聯表的語言做**檢定**（條件獨立、階層
交互），用迴歸的語言做**估計**（係數、區間），兩者互相印證。

| 方法 | 在本題能回答什麼 |
|---|---|
| 對數線性模型 | 直接建模整張表，不必先選一個結果變數 |
| 條件獨立性檢定 | 「給定機場與天氣等級，歸因類別與公司是否獨立」即本題的虛無假設 |
| 高階交互的階層檢定 | 公司 × 天氣 × 歸因的三階交互，對應「不同公司對天氣惡化的歸因反應不同」 |
| CMH 檢定 | 機場 × 月分層下檢定公司與歸因的關聯。**幾乎是現行識別策略的無母數版本**，適合作為主模型的穩健性對照 |
| Simpson 悖論的正式檢查 | 聚合到主線後效應收縮的現象（見 `findings.md`），列聯表框架有處理它的標準語言 |

GLM 是現行方法的母框架（logistic 即其特例），但幾個部分尚未用到：

| 方法 | 在本題能回答什麼 |
|---|---|
| 連結函數的選擇 | binary part 現用 binomial GLM with identity link。**cloglog 值得一試**——事件機率不對稱時比 logit 適合，而陽性比例偏低。若把天氣歸因視為潛在觸發過程，「至少一次觸發」的機率正好是 cloglog |
| 準概似 | 不指定完整分布，只指定均值-變異數關係。fractional logit 即屬此類 |
| GEE | 層內相關的替代處理。現用 cluster-robust 標準誤，GEE 是同一問題的另一解，且能估出工作相關結構 |
| 偏差殘差與 GLM 診斷 | 現行診斷用的是 OLS 殘差，GLM 有專門的殘差定義 |

## 隨手可做的簡單檢驗

成本低、不須建模，但能擋掉具體的質疑或指出下一步。

| 檢驗 | 回答什麼 |
|---|---|
| 卡方 / Fisher 精確檢定 | 公司 × 歸因類別在單一機場內是否獨立。樣本少的表用 Fisher |
| CMH | 上者的分層版本，控制機場與月 |
| 比例檢定與其信賴區間 | 兩家公司的歸因率差異，不經模型 |
| KS 檢定 | **`oracle_` 子樣本的代表性**——該子樣本僅涵蓋部分資料，若氣象分布與全樣本不同，穩健性結論的外部效度有問題。看統計量而非 p 值（大樣本下必顯著） |
| 尾數分布的卡方 | 申報分鐘數是否過度集中於 5、10 的倍數，見「計數與堆積」 |
| complete separation 的檢查 | 逐一檢查是否存在結果全同的公司 × 機場單位，決定是否需要 Firth |
| 過度離散檢定 | 若改用計數模型，決定 Poisson 或負二項 |
| 方差膨脹因子 | 已做。判準見 `decisions.md`——共線是否要處理取決於共線變數是不是交付物 |

**大樣本下 p 值幾乎必然顯著**，故這些檢驗一律看**效應量**，p 值只用於排除
「連效應量都很小卻仍不顯著」的情況。逐變數的例行分布檢定不做——模型不假設
解釋變數的邊際分布，檢定一個模型不依賴的東西導不出任何行動。

## 識別與因果

| 方法 | 在本題能回答什麼 |
|---|---|
| 雙重差分 | 同一執飛者換主線即為自然實驗，用於支線歸屬 |
| 事件研究 | era 交互的替代做法，看歸因行為如何隨時期演變 |
| 合成控制 | 單一公司的制度變動如有明確時點可用 |
| 三重差分 | 支線歸屬疊加天氣條件，分離「主線系統」與「天氣嚴重度」 |
| 高維固定效應 | 公司 × 機場 × 時段多向固定效應的一次吸收，取代現行手工去均值 |
| 交互固定效應 | 若存在未觀測的共同衝擊（如全國性航管政策）且各公司載荷不同 |
| 邊界分析 / bunching | 申報門檻在 15 分鐘，門檻附近的分佈堆疊本身即是操縱證據 |
| 敏感度分析（未觀測混淆） | 要多強的未觀測混淆才能改變某家公司的結論。監理清單被質疑時的標準防線 |
| 部分識別 / bounds | 無法點識別時給出區間，比放棄整個問題好 |

## 異常偵測導向

歸因異常稽核本質接近異常偵測，但本題要的是**可解釋的排序**，不是黑箱分數。
以下僅在能導出可解釋輸出時採用。

| 方法 | 在本題能回答什麼 |
|---|---|
| 殘差型異常偵測 | 以誠實基準的預測殘差定義可疑度（注意：兩步殘差法的不確定性問題見 `decisions.md`） |

## 機器學習作為輔助而非主力

交付物是係數與排序，不是預測準確度。ML 僅用於以下輔助用途。

| 方法 | 在本題能回答什麼 |
|---|---|
| 梯度提升樹 | 建立誠實基準的柔性函數形式，或檢查是否遺漏重要交互 |
| 雙重機器學習 | 以 ML 學習高維干擾參數（氣象、班表），同時保留公司主效應的有效推論 |
| 因果森林 | 歸因異常的異質性——在哪些機場、哪些天氣條件下更明顯 |
| SHAP / 變數重要度 | 僅作為診斷，不作為交付物的證據 |

## 擴充方向

**本節是決定下一步時的入口。**上方各節依方法的類型組織（供查「某類方法有
哪些」），本節依**先後順序**排列。兩者有重疊，重疊處以本節的順序為準。
各方法的模型、假設與出處見 `report/methods_doc.typ` 與 `literature.md`。

### 排序判準

依序看四件事：是否為其他項目的前提、對「方法嚴謹」的貢獻、成本、得不到結論
的風險。**不依方法的精巧度**——評分看方法嚴謹，而嚴謹不等於方法多。

此排序定於任何一項執行之前，依的是結構與成本的判斷，不是結果。表中的風險
一欄是當時的預期，實測的結果見下方。

### 順序

| 方法 | 解決什麼 | 排在此處的理由 | 主要風險 |
|---|---|---|---|
| 模擬研究的骨架：只做 H₀ 情境，量單次配適時間 | 資料沒有真實成因，方法能否找回已知偏移只能在真值已知處量測 | 其餘方法的假設檢查半數落在模擬；配適時間決定後面的規模 | 單次配適太慢，重複次數不足 |
| 三種氣象設定並列：`wx_`、`oracle_`、兩組並用 | 只用 `wx_` 是以少於申報人的資訊評斷其申報 | 成本最低，且回應最容易被問的質疑。`explore/oracle_alignment.py` 已有雛形 | 幾乎沒有 |
| negative control 與補集樣本 | 參照點是「沒有觀測到的天氣」而非其他公司；補集檢查結論是否依賴樣本以哪組氣象判定 | 唯一不靠因子水準間比較的方向性證據，也是 empirical null 的前提。航班已在 `audit_clean.parquet` 內 | 層改取航線 × 年月後，含兩家以上公司的層太少 |
| test of restrictions 轉為正式腳本：天氣變化 × 公司、對實際天氣的 monotonicity、前一航段剩餘緩衝 × 公司 | 由申報的機械關係導出應成立的限制，檢驗各公司是否違反 | 三項皆有探索腳本或現成欄位，成本低 | 剩餘緩衝的分位數切點是選定值 |
| confidence set for ranks | 交付物是排序，現有區間卻是係數的區間 | 直接對應交付物，輸入只需係數與共變異矩陣 | 集合太寬，排序失去意義 |
| 區間有效性：cluster bootstrap、two-way jackknife | rank 的推論以係數區間為輸入，區間失準則其後全部失準 | 緊接 rank 的推論，併入模擬研究量測涵蓋率 | 計算量大 |
| empirical null | 樣本量大時任何差異皆顯著，理論的虛無分布沒有鑑別力 | 依賴 negative control 的結果 | 公司層級的資料點只有公司數那麼多，參照分布的離散估不準 |
| 未觀測混淆的敏感度分析 | 要多強的未觀測混淆才能改變某家的結論 | 標準防線，計算便宜，但只量化既有結論的脆弱度，不產生新證據 | 公司在層內才有變異，partial R² 的公式須修正 |
| 機尾號固定效應：限於區域航空之間 | 消去機隊特性 | 跨公司執飛的飛機只把區域航空連成一個連通成分，主線公司各自孤立 | 主線公司不可識別 |
| 機場層級清單：交叉分類隨機效應的階層模型，Firth 懲罰概似只用於少數 separation 的單位 | 「查某公司在哪些機場」比「查某公司」可執行 | 工作量最大，且以公司層級的方法通過模擬驗證為前提 | 機場內公司數少時，公司 × 機場的效應與機場的效應難以分開 |
| 曝露時間窗 | 以機場逐時氣象把「惡劣與否」換成連續的曝露量 | 延伸項，時間不足即不做 | 邊際貢獻不明 |

### 實測引出的方向

上表各項實測後，另有四項由實測結果引出，同樣已實測。它們不改動上表的順序，
各自併入對應的項目。

| 方法 | 解決什麼 | 併入何處 | 主要風險 |
|---|---|---|---|
| 以全體已執飛航班為分母的估計對象 | 樣本以延誤達申報門檻為條件，而公司本身影響航班是否達門檻 | 與三種氣象設定並列同一層級：現行估計對象與此估計對象並列 | Lee 式 bounds 沒有資訊，只能並列兩個估計對象，不能給界 |
| 公司 × 天氣狀態的交互作用 | 把公司主效應分成天氣良好時的部分與隨天氣變化的部分 | negative control 之後 | 加法與乘法尺度下排序不同，回答的問題也不同，須兩者並列 |
| 分級的決策規則 | 交付物為分級時，分幾級、切在哪 | confidence set for ranks 之後 | 結果由「預計查核的比例」決定，須明示並並列數個值 |
| 由 BTS 定義導出的規則，配 FAA 的地面延誤計畫公告 | 不靠因子水準間比較的預期申報 | 延伸項，與曝露時間窗同級 | 公告只能逐則取得；條文把判斷交給公司 |

### 實測後的調整

各項的可行性已以 `scripts/explore/` 的腳本實測，結論見 `findings.md`
「擴充方向的可行性」。順序不變，以下三項的做法依實測修訂：

- **模擬與 bootstrap 不必抽取部分的層**。單次配適的時間容許完整樣本重複數百次，
  Poisson 模型須平行執行
- **negative control 以機場 × 年月為主要設定**。航線 × 年月的層可比較的航班
  不及半數，降為檢查
- **交付物以分級呈現**。rank 的信賴集合在清單兩端窄、中段寬，完整排序沒有
  依據

### 未排入的項目

記錄於此，避免重複評估。

| 方法 | 為何未排入 |
|---|---|
| 邊界分析（bunching） | 申報門檻在 15 分鐘，門檻附近的分布堆疊不需因子水準間的比較即可作為證據。但現行樣本已由該門檻界定，門檻下方的航班須自原始檔重取；且到達延誤由實際與排定時刻相減而得，公司不直接填寫，操縱空間存疑 |
| 巢狀 logit | 把「是否訴諸免責事由」設為獨立的第一層決策。two-part model 已分開這兩個決策，增量有限 |
| 時間維度的正式建模：變點偵測、動態係數、事件研究 | 公司 × 時段的交互作用已記錄行為隨時期改變，正式建模主要是精緻化。除非能定位到具體的制度變更時點，否則邊際貢獻有限 |
| 逐期監測（risk-adjusted CUSUM） | 幾乎每家公司都越界，偵測到的是全體公司隨時期的變動；in-control 的基準期不成立。須先扣除時期效應才有意義 |
| 以 `oracle_` 校正 `wx_` 的量測誤差 | 兩組氣象不是同一時點的重複量測，古典量測誤差的假設不成立。以工具變數重估只作為三種氣象設定並列之下的一項檢查 |
| Y2 的廣義有序模型 | 可同時檢視所有切點，是質量點分解的推廣。Y2 只輔助解讀，不產出清單的數字 |

## 目前判斷用不上

記錄理由，避免重複評估。

| 方法 | 為何用不上 |
|---|---|
| 時間序列（AR / ARMA / 單根 / GARCH） | 分析單位是航班列，不是時間序列。除非改以「公司 × 月」的歸因率序列為對象，那是另一個研究問題 |
| 可靠度分析 / 存活分析 | 無設限資料結構；延誤分鐘數不是壽命 |
| SVM / RKHS | 預測導向且不可解釋，本題要的是係數與區間 |
| Copula | 兩部的公司主效應明確不合成單一分數，相依結構不是交付物的一部分 |
| 空間統計 | 機場已由固定效應吸收，殘餘的地理相關性不是研究問題 |
| 網路分析 | 延誤傳播已在 `design.md` 列為未納入方向 |
