### 有序解釋變數的設定

`wx_*_flight_category_ordinal`（VFR < MVFR < IFR < LIFR）目前**當連續變數放入**，
隱含「每一級的效果等距」。此假設幾乎確定不成立——IFR 惡化到 LIFR 對申報行為的
影響應遠大於 VFR 到 MVFR。變數只有四級，改為 dummy 的成本極低（多兩個參數），
且移除一個不必要的假設。**屬設定正確性問題，須實測確認公司效應是否因此改變。**

### 計數與堆積

申報分鐘數是整數，目前只用於構造比例，未直接建模。

| 方法 | 在本題能回答什麼 |
|---|---|
| Poisson / 負二項 | 直接建模天氣分鐘數而非比例；負二項處理過度離散 |
| 零膨脹計數 / hurdle 計數 | 上表的零膨脹寫在連續脈絡下，計數版本的零生成機制不同 |
| **堆積模型（heaping）** | 人工填報會把分鐘數湊整到 5、10、15、30 的倍數。**湊整程度本身即申報品質指標**，且人工與系統自動填報的湊整型態不同，正可對應混合模型中「預設值成分」的解釋。與下方 Benford 類檢定同一思路，但能估出各公司的湊整傾向而非僅做檢定 |
| 過度離散檢定 | 決定 Poisson 或負二項 |

### 多類別歸因的完整處理

「延誤記到哪一欄」是五類選擇，目前 Y3 只取其中兩類的比值。

**已採用多項 logit**，以 Poisson 對數線性的等價形式求解，理由與實作限制見
`decisions.md`。係數在雙重基準下可直接解讀，不需換算邊際效應。

其餘選項與現況的關係：

| 方法 | 在本題能回答什麼 |
|---|---|
| 巢狀 logit | 決策可能是階層的：先定「是否免責事由」（weather + NAS vs carrier + late-aircraft），再定哪一個。比扁平多項更貼近實際決策結構。**現行扁平設定已能分辨「集中導向單一事由」與「整體遠離可歸責」兩種型態**，巢狀的增量在於把後者正式化為第一層的係數 |
| 有序模型（按免責程度） | 若接受 weather > NAS > late-aircraft > carrier 的免責排序，則歸因是有序結果，比多項精簡。**此排序是推論而非 BTS 官方定義，須先辯護** |
| 卡方適合度 | 各公司的成因分配是否來自同一多項分布。多項 logit 已給出帶區間的係數，此檢定的增量有限 |

### 二元資料的小樣本問題

| 方法 | 在本題能回答什麼 |
|---|---|
| Firth 懲罰似然 | 樣本少的公司 × 機場格子可能完美分離，係數發散。清單要附區間就必須處理。**單體的 Poisson separation 不需要它**，理由見 `decisions.md` |
| 稀有事件 logit（King-Zeng） | Y1 的陽性比例不高，小格子內更稀 |
| 條件 logit | 概念上正確的固定效應處理。`ConditionalLogit` 的實作在本資料上不可用（見 `decisions.md`），但那是實作限制，不是方法本身的問題 |

## 列聯表與 GLM 框架

本題的資料結構本質是一張高維列聯表：**公司 × 機場 × 月 × 天氣等級 × 歸因類別**。
前四維是分層，最後一維是結果。現行的「格子內去均值」就是在這張表裡做條件
比較，只是以迴歸的形式表達。

**對數線性模型與多項 logit 等價**，故此節與「多類別歸因的完整處理」不是兩套
方法，而是同一件事的兩種表達。可用列聯表的語言做**檢定**（條件獨立、階層
交互），用迴歸的語言做**估計**（係數、區間），兩者互相印證。

| 方法 | 在本題能回答什麼 |
|---|---|
| 對數線性模型 | 直接建模整張表，不必先選一個結果變數 |
| 條件獨立性檢定 | 「給定機場與天氣等級，歸因類別與公司是否獨立」即本題的虛無假設 |
| 高階交互的階層檢定 | 公司 × 天氣 × 歸因的三階交互，對應「不同公司對天氣惡化的歸因反應不同」 |
| CMH 檢定 | 機場 × 月分層下檢定公司與歸因的關聯。**幾乎是現行識別策略的無母數版本**，適合作為主模型的穩健性對照 |
| Simpson 悖論的正式檢查 | 聚合到主線後效應收縮的現象（見 `findings.md`），列聯表框架有處理它的標準語言 |

GLM 是現行方法的母框架（logistic 即其特例），但幾個部分尚未用到：

| 方法 | 在本題能回答什麼 |
|---|---|
| 連結函數的選擇 | Y1 現用恆等連結（線性機率模型）。**cloglog 值得一試**——事件機率不對稱時比 logit 適合，而 Y1 的陽性比例偏低 |
| 準概似 | 不指定完整分布，只指定均值-變異數關係。fractional logit 即屬此類 |
| GEE | 格子內相關的替代處理。現用 cluster 標準誤，GEE 是同一問題的另一解，且能估出工作相關結構 |
| 偏差殘差與 GLM 診斷 | 現行診斷用的是 OLS 殘差，GLM 有專門的殘差定義 |

## 隨手可做的簡單檢驗

成本低、不須建模，但能擋掉具體的質疑或指出下一步。

| 檢驗 | 回答什麼 |
|---|---|
| 卡方 / Fisher 精確檢定 | 公司 × 歸因類別在單一機場內是否獨立。小格子用 Fisher |
| CMH | 上者的分層版本，控制機場與月 |
| 比例檢定與其信賴區間 | 兩家公司的歸因率差異，不經模型 |
| KS 檢定 | **`oracle_` 子樣本的代表性**——該子樣本僅涵蓋部分資料，若氣象分布與全樣本不同，穩健性結論的外部效度有問題。看統計量而非 p 值（大樣本下必顯著） |
| 尾數分布的卡方 | 申報分鐘數是否過度集中於 5、10 的倍數，見「計數與堆積」 |
| 完美分離的檢查 | 逐格檢查是否存在結果全同的公司 × 機場格，決定是否需要 Firth |
| 過度離散檢定 | 若改用計數模型，決定 Poisson 或負二項 |
| 方差膨脹因子 | 已做。判準見 `decisions.md`——共線是否要處理取決於共線變數是不是交付物 |

**大樣本下 p 值幾乎必然顯著**，故這些檢驗一律看**效應量**，p 值只用於排除
「連效應量都很小卻仍不顯著」的情況。逐變數的例行分布檢定不做——模型不假設
解釋變數的邊際分布，檢定一個模型不依賴的東西導不出任何行動。

| 方法 | 在本題能回答什麼 |
|---|---|
| 雙重差分 | 同一執飛者換主線即為自然實驗，用於支線歸屬 |

## 擴充方向

**本節是決定下一步時的入口。**上方各節依方法的類型組織（供查「某類方法有
哪些」），本節依**要解決的問題**組織並排序。兩者有重疊，重疊處以本節的
優先順序為準。

清單的必要路徑已完成，以下皆為加分項。**依對報告的實質貢獻排序，不依方法的
精巧度**——評分看方法嚴謹，而嚴謹不等於方法多。每項標明它解決什麼問題。

### 一、獨立於同儕比較的證據（價值最高）

現有證據絕大多數是「A 比 B 高」。混合模型那條線之所以最強，正因為它有
**內生錨點**（「延誤越長越不該整段全掛」是機械性的預期）。同類證據愈多，
清單被質疑時的防線愈厚。

**已有兩個內生錨點**：混合模型的延誤長度、前一航段的尾機壓力，見
`findings.md`。兩者機制不同而指向同一家公司。

| 方法 | 解決什麼 |
|---|---|
| **邊界分析（bunching）** | 申報門檻在 15 分鐘，門檻附近的分佈堆疊即操縱的直接證據。**不需同儕比較**，但現行樣本已由該門檻界定，門檻下方不在樣本內，須自原始檔重取 |
| 單調性檢定 | 「天氣越差越該歸因天氣」是可施加的形狀約束，違反處即為訊號 |
| 敏感度分析（未觀測混淆） | 要多強的未觀測混淆才能推翻某家的排名。被質疑時的標準防線 |

### 二、不確定性的正確傳遞（真正的技術缺口）

交付物是**排序**，但現有區間是**係數**的區間。監理單位問的是「排第一的
有多穩」，兩者不同。

| 方法 | 解決什麼 |
|---|---|
| 排序推論 / rank set | 直接對名次做推論 |
| Bootstrap 名次區間 | cluster bootstrap 重抽，看名次的分布 |
| 多重檢定校正（FDR） | 十幾家同時檢定，清單要能被採信就繞不開 |
| 同時信賴帶 | 整張清單同時成立的覆蓋率 |

### 三、歸因的完整結構

Y3 只看 weather 對 NAS，但延誤實際記到五個欄位，carrier 與 late-aircraft
的資訊目前被丟掉。

**此項已完成**，見 `findings.md`。單體約束經實測在樣本內嚴格成立，故這是
目前辯護力最強的一條——約束是資料結構的客觀事實，不是選定的設定。對數比
轉換已否決，理由見 `decisions.md`。

氣象控制已補上，見 `decisions.md`。剩餘的增量：

| 方法 | 解決什麼 |
|---|---|
| 巢狀 logit | 把「是否訴諸免責事由」正式化為獨立的第一層決策 |

### 四、清單的粒度：機場層級

目前只到公司。監理單位要派人去查，「查某公司在哪些機場」比「查某公司」
可執行得多。工作量大於前三項，且會引出新的識別問題。

| 方法 | 解決什麼 |
|---|---|
| Firth 懲罰似然 | 格子的完美分離普遍，標準 logit 會發散 |
| 階層模型 / 部分池化 | 該層樣本稀疏，收縮預期會**實質起作用**（不同於公司層級的無感） |
| 交叉分類隨機效應 | 公司 × 機場為非巢狀結構 |

### 五、時間維度的正式建模

era 交互與 hold-out 皆顯示行為隨時期漂移，但兩者都是粗糙分段。漂移已被
記錄，正式建模主要是精緻化——**除非能定位到具體的制度變更時點**，否則
邊際貢獻有限。

| 方法 | 解決什麼 |
|---|---|
| 變點偵測 | COVID 切點現以規則定出，可改為模型估計並附不確定性 |
| 狀態空間 / 動態係數 | 讓公司效應隨時間平滑演化，而非三段跳 |
| 事件研究 | 圍繞特定時點看效應軌跡 |

### 其他已記錄的擴充

- Y2 的廣義有序模型，可同時檢視所有切點，是 one-inflated 的自然推廣
- 機場逐時氣象支撐的天氣持續時間與惡化軌跡（見 `data.md`）

## 目前判斷用不上

記錄理由，避免重複評估。

| 方法 | 為何用不上 |
|---|---|
| 時間序列（AR / ARMA / 單根 / GARCH） | 分析單位是航班列，不是時間序列。除非改以「公司 × 月」的歸因率序列為對象，那是另一個研究問題 |
| 可靠度分析 / 存活分析 | 無設限資料結構；延誤分鐘數不是壽命 |
| SVM / RKHS | 預測導向且不可解釋，本題要的是係數與區間 |
| Copula | 三個 Y 明確不合成單一分數，相依結構不是交付物的一部分 |
| 空間統計 | 機場已由固定效應吸收，殘餘的地理相關性不是研究問題 |
| 網路分析 | 延誤傳播已在 `design.md` 列為未納入方向 |
