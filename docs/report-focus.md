# 報告的研究目標與論證

## 核心目標

評估平台局前評分是否已充分反映近期表現，以及加入雙方近期戰績與評分不確定性後，對局結果的預測改善是否穩定、集中在哪些玩家與情境。

「充分」限於可觀察歷史及指定模型的比較，不是宣稱檢定所有歷史與結果的條件獨立性。主要交付為局前勝、和、負機率與時間外增量評估；機率改變不等於玩家勝率被提高，預測改善也不等於應用決策收益。

## 報告的論證順序

報告先用評分已包含戰績的問題引入，說明 RD 與分析單位，再介紹三個模型及同一匿名對局的預測輸出。主講以時間切分圖交代估計、選項、重估與測試，接著以 log loss 與得分 MSE 並排檢查近況效果，再呈現 RD 延伸、相對改善、機率調整幅度與校準。MSE 只評估期望得分，不取代三類機率的 log loss。機率調整和校準分頁，後者展示 Blitz 兩段測試的共同分箱得分偏差。正文保留首局與缺歷史、OGS 與 AoE2、序列診斷、玩家權重及長視窗支持，依「為何嘗試、發現什麼、如何影響判斷」組織。這是分析過程報告，未形成通用修正或部署結論的嘗試仍須交代。序列模擬用流程圖說明固定特徵的限制，累積偏差與有效玩家數依視窗長度上下對照。樣本規模、評分基準、雙方近況、RD 交互作用與累積偏差定義均置於正文，接在對應問題之後；重複的欄位、機率與推論範圍說明合併，不設附錄。主講區分制度分組、模型設計取捨與測試結果，不將候選未選入解讀為無作用。

Lichess 以「高 RD 對局」及「雙方低 RD 對局」稱呼任一方達平台門檻與否的分組；既有圖的 novice／established 對應此定義。AoE2 則依累計局數分組，不能視為相同族群。方法來源保留於[方法評讀](background/competitive-game-methods.md)，供研究查核。

| 問題 | 分析與證據 | 判讀邊界 |
|---|---|---|
| 評分資訊之外是否仍有近況資訊？ | 含 RD 基準與雙方近況模型，在相同後續玩家局比較 | 基準形式、實力追蹤與心理機制不能由預測增量分開 |
| 改善是否穩定、集中在哪裡？ | 向前時間切分、任一方 RD 分組、RD 與近期變動交互作用 | 模型選項限訓練內部，測試資料已使用，保留探索定位 |
| 改善是否具有實際幅度？ | 相對損失下降、機率調整分布、訓練期選取的匿名示例 | 不設定事後實用門檻，不把示例當個別機率驗證 |
| 哪些情境不能直接沿用？ | 缺歷史與首局、跨遊戲的資料條件 | OGS 只有結束時間；AoE2 僅短期快照，沒有 RD |
| 單局模型能否支持玩家戰績警示？ | 固定機率的連敗與累積偏差參考、兩種玩家權重 | 人工參考未重建歷史回饋及續下，不作生成虛無檢定 |

## 主張與範圍

近況對部分速度與時段提供小幅的時間外增量，新手組較集中，老手不一致。可交付有條件的機率修正與適用範圍，不能宣稱已識別 tilt、證明配對操控或找到休息介入的效果。

配對、提醒、因果補充與停止規則的成果保留於各自文件，並非這份報告的並列目標。序列診斷展示從單局預測走向戰績判讀時，模擬設定、玩家權重與樣本支持如何限制結論。既有前瞻登記與結果不更動，也不把本次探索重新標為確認性證據。

## 交付與檢查

投影片為 `report/baseline.typ`，逐頁講稿為 `report/baseline_script.md`，PDF 為 `report/baseline.pdf`。投影片與口稿逐頁對應，不列時間估計。

口稿採正式報告的口頭語氣，直接交代研究動機、資料定義、方法選擇與結果解讀。避免聊天式問句、個人感想、逐頁旁白及方法來源敘事；影響統計解讀的限制隨相關內容說明。

所有估計量與樣本數由既有 `outputs/` 圖表讀入。`scripts/prediction_report.py` 將既有序列、機率變化與校準摘要畫為報告用圖，不重估模型。`make check-slides` 檢查頁面溢出，`make check-report-captions` 與 `make lint` 檢查文件及程式規範。
