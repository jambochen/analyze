# 分析計劃

依研究問題排列的方法、各方法的定位、結論之間的依賴與待辦。各分析的結論見 `docs/results/`，總覽見根目錄 `README.md`。研究問題見 `docs/design.md`；各方法的模型、假設與統計依據見 `docs/methods.md`。

## 框架

- **推論的依據**：因果補充的推論只依賴 2014 年 arena 已知的隨機配對機制，以批內 permutation test 推論；模型只用來提高精度與換算效果的大小
- **檢定的優先序**：概似比檢定優先，其次 score 檢定，最後 Wald 檢定；資料有玩家與 dyadic 相依時用修正版。信賴區間可用 delta method（`docs/methods.md`「檢定與區間」）
- **方法的定位**：每個方法屬主要做法、對照、退路之一，在分析之前寫定，不看結果再挑方法
- **基礎方法優先**：有更簡單而同樣嚴謹的做法時不用複雜模型；選對照時優先用修課教過的模型
- **範圍以交付物為準**：交付物包含共用機率診斷、平台配對、玩家戰績解讀與適用範圍，問題結構見 `docs/application-scope.md`。停止規則暫停延伸、既有成果保留；正文是否納入依篇幅決定
- **預測與因果的解讀分開**：主線以完整時間外預測與校準評估，跨遊戲各自估計；「剛被分到強對手使下一局變差」這個因果解讀只依據隨機配對。剛輸之後的偏差來自 tilt 還是等級分調得不夠，本資料分不開，不再追究，報告寫成限制
- **前瞻驗證已完成**：2015 年 1 月 1 日至 4 月 19 日的 arena 登記與結果保留。新假設另立登記；既有資料作探索，確認性驗證須另留未使用資料

## 執行優先序與完成條件

| 優先序 | 工作 | 完成條件 |
|---|---|---|
| 玩家用途 | 近期表現提醒 | 已比較提醒頻率、下一局殘差、等玩家權重及月份敏感度；見 `docs/results/player-alerts.md`，不延伸為休息效果 |
| 實際用途 | 固定批次替代配對 | 保留無法重配的批次在分母；比較平均、極端對局、批內最差與個人保護目標，交叉報告模型評分及玩家局代價，規格見 `docs/matching-policy.md` |
| 優先 | 完整時間外驗證 | 主基準、校準與近況模型都只用訓練期資料；產出共同測試樣本的分數差、區間與校準圖 |
| 其次 | Lichess、OGS、AoE2 的共同評估 | 列出資料與模型差異，並列遊戲內增量改善、新手與老手結果、適用範圍 |
| 延伸 | 新手的剩餘誤差 | 核對已有 RD 交互作用分析後寫定候選，以完整時間外評估判斷是否保留；不改善也作結論 |
| 共同基礎 | 首局與開局間隔 | 已比較固定模型、重新校準與情境增量，分缺歷史與兩種玩家權重；見 `docs/results/entry-context.md` |
| 適用範圍 | 低 RD 與訓練支持範圍 | 已比較同集合模型表現、校準與排除群體，未作通用可靠性規則 |
| 待驗證 | 模型維護決策 | 用前期資訊決定後期維持、回退或更新，再評估後期收益；月份診斷不視為已完成此策略 |

固定批次的平均、極端對局、最差配對、個人限制及同分解保護比較已執行，包含玩家自身 RD 的代價分組；結果與等待代價的可識別界線見 `docs/results/matching-policy.md`。

共同規格見 `docs/methods.md`「共同預測驗證」。以下方法清單同時收錄既有分析；保留規格不表示需全部重跑。具體切分與候選見 `docs/temporal-validation.md`，三項分析已執行，結果與限制見 `docs/results/temporal-validation.md`。不增加第四個遊戲，不擴充停止規則。

## 研究問題與方法

### 地基：資料與定義

| 項目 | 回答 | 文件 |
|---|---|---|
| 連續對局與流失的定義 | 續下、離開、回訪的操作定義 | `docs/data/sessions.md` |
| arena 配對批次的重建 | 每次配對時同時空閒的玩家；permutation test 的打亂範圍 | `docs/results/random-pairing.md` |
| Glicko-2 重放 | 每局對局前的 rating deviation | `docs/data/glicko-replay.md` |
| 速度類別 | 等級分屬於哪一個類別 | `docs/data/speed-class.md` |
| 新手期 | 等級分尚未收斂的對局如何界定 | `docs/results/novice-period.md` |
| 配對來源 | API 的 `source` | `data/raw/lichess-game-meta/` |

### 期望勝率是否校準

| 定位 | 方法 |
|---|---|
| 主要做法 | 三個基準（有序 logistic、Glicko 形式、加入 rating deviation 的有序 logistic）巢狀於第三者，以修正的概似比檢定比較 |
| 對照 | 樣本外對數分數與 ranked probability score |

- **輸出**：主基準為加入 RD 的有序 logistic；Elo 形式哪裡偏（`docs/results/calibration.md`、`docs/results/expected-score-baselines.md`）

### 剛被分到強對手之後，期望勝率是否又錯一層

| 定位 | 方法 |
|---|---|
| 主要做法 | 總效果：上一局所屬批內重新配對的 permutation test |
| 主要做法 | 直接效果：基準變數自由估計的有序 logistic，殘差做玩家內對比，配對 $t$ 檢定 |
| 主要做法 | 輸棋本身的效果（平均得分差的比值）；勝負兩邊的對稱性；劑量反應 |
| 對照 | 玩家斜率的 $t$ 檢定；以局加權的修正概似比檢定與玩家 bootstrap；只用純隨機規則的批；每批一個截距的 score 檢定與各批 odds ratio 的加權平均 |

- **輸出**：`docs/results/crossover.md`

### 續下的選擇

| 定位 | 方法 |
|---|---|
| 主要做法 | 續下的 logistic 迴歸；單調性的檢查；修剪上下界 |
| 對照 | 不假設單調性的界限；倒數機率加權；選擇上的有參數敏感度分析 |

- **輸出**：`docs/results/continuation.md`

### 等級分在剛輸之後是否失準

| 定位 | 方法 |
|---|---|
| 主要做法 | 依 RD 與上一局結果分層的校準迴歸檢定；校準迴歸中加入上一局等級分變動的概似比檢定，與它隨 RD 變化的交互作用檢定 |
| 描述 | 依 RD 與上一局結果分層的校準曲線 |

- **輸出**：`docs/results/rating-filter.md`。RD 的五等分幾乎沒有 RD 的差異，照事先的切法報告，不改切法重跑

### 依狀態調整的勝率（預測交付物）

| 定位 | 方法 |
|---|---|
| 主要做法 | 主基準作 offset 的有序 logistic，依序加入 arena 的整體校正、上一局結果、上一局等級分變動、對手的同一組近況（雙方共用係數、取差）；各項是否加入由樣本外對數分數決定，不由前局效果是否顯著決定 |
| 對照 | LightGBM、XGBoost 與 MLP，輸入相同，只作預測上限的參照 |

- **前置**：主基準；等級分是否失準
- **評估**：2014 年依時間分成估計與評估兩段；對數分數、ranked probability score、校準曲線
- **輸出**：修正後的勝、和、負機率，與「再開一局，預期比系統的期望差多少」（`docs/results/state-adjusted-probs.md`）

### 歷史對局的長度

| 定位 | 方法 |
|---|---|
| 主要做法 | 主基準作 offset 的高階 Markov（前一至三局的結果組合），以樣本外對數分數決定階數 |
| 主要做法 | HMM：同場內持續的短期狀態，以 forward filter 的一步預測評估 |

- **前置**：主基準；依狀態調整的勝率的樣本
- **輸出**：依狀態調整的勝率只用上一局的依據；有沒有持續數局的失常狀態（`docs/results/history-depth.md`）

### 停止規則（既有成果，暫停延伸）

本節保留既有回測規格與結果，不列必要交付，不追加分組、權重或影響度回測。

| 定位 | 方法 |
|---|---|
| 主要做法 | 回測：事先寫定的規則（一路下到第一次輸、連輸兩局才停）套到實際序列，比較保留與刪去的局的平均殘差，以「從不停」為基準；玩家 block bootstrap，多條規則以 Holm 法校正 |
| 主要做法 | 隔天重置：刪去的局與隔天第一局的殘差比較；後者不比前者好時，停下只是把虧分延後 |
| 主要做法 | 「規則沒有用」的結論以區間落在事先寫定的邊界內判定，邊界以等級分換算；區間跨出邊界的記為樣本不足以判斷，不寫成沒有效果 |

- **前置**：主基準；續下的選擇（回測只刪局，針對的是續下者）
- **輸出**：民間規則有沒有用，依速度類別與新手與否報告（`docs/results/folk-stop-rules.md`）；「不必停」的結論須有區間落在邊界內

### 玩家間的差異

母體平均沒有效果不表示每個人都沒有；Gee 等人（`docs/background/literature.md`）的結論即全體無、少數個別有。這一節只作補充檢查，用最簡單的做法。

| 定位 | 方法 |
|---|---|
| 主要做法 | 每位玩家殘差對 $h$ 的斜率，其加權變異數與批內重新配對的虛無分布比較 |

- **前置**：主基準；依狀態調整的勝率
- **解讀**：虛無分布不拒絕時，建議維持對全體的結論；拒絕時，先確認異質性不是少數重度玩家的雜訊；本計劃不因此追加停止規則回測（有效玩家數見 `docs/methods.md`「檢定與區間」）
- **與 Gee 等人的對照**：本研究用 arena 的隨機配對識別，他們靠模型控制；兩者在玩家異質性上的結論是否一致，是報告可以直接對照的一點

### 前瞻驗證（已完成）

本節記載已完成的登記設計與輸出，新延伸不回寫其假設或判定規則。

- **登記文件**：主基準、檢驗的量、判定規則、檢定水準與方向、最小可偵測效果與檢定力。檢定力以 2014 年的變異量與 2015 年樣本的有效玩家數計算，登記時若偵測不到所要的效應大小，須寫明，不等用完才發現
- **檢驗的量**：Blitz 剛被分到強對手之後的總效果；依狀態調整的勝率的樣本外對數分數；停止規則回測中勝過「從不停」的規則
- **判定規則**：2015 年的總效果以單尾檢定拒絕「效果不在 2014 年的方向」，且兩年的效果以同質性檢定不拒絕，並報告兩年差值的信賴區間
- **一併登記的事後型態**：上一局等級分變動的係數為正；剛贏之後好於期望；高 RD 剛輸之後差於期望；LightGBM、XGBoost 與 MLP 在新手組的對數分數好於依狀態調整的勝率；每天第一局低於期望。這五項是看過 2014 年結果後才形成的，只在 2015 年的樣本上檢驗方向
- **輸出**：總效果與修正後的勝率通過；停止規則為樣本不足以判斷（`docs/results/prospective-validation.md`）

### 修正後勝率的呈現

- 修正量以等級分表示，依速度類別與雙方上一局結果的組合畫成一張圖；Blitz 與 Classical 另示等級分變動的斜率
- 修正量附區間：修正量是近況係數的線性組合，以 dyadic sandwich 的共變異數經 delta method 求得。主基準作 offset、視為已知，它以全站對局估計，樣本遠大於 arena 的上半年
- 只做預測；民間停止規則的回測另在停止規則一節呈現

### 連勝連敗是否超出期望

回應電競玩家「系統故意製造連敗」的指控，為主題新穎的加分項。

| 定位 | 方法 |
|---|---|
| 主要做法 | 連輸（連勝）$k-1$ 局之後的局，其得分減期望得分的平均；$k = 5$ 事先指定。殘差在期望勝率正確下是 martingale 差分，不需要續下模型；dyadic 標準誤 |
| 對照 | 依序以系統的期望勝率、主基準、依狀態調整的勝率為基準，看超額是否在最後一個基準下消失 |

- **資料**：各自的評估段：Lichess 2014 年下半年 arena 的 Bullet 與 Blitz；OGS 2023 年；AoE2 2026 年 6 月 24 日之後、整天接得上的天
- **解讀的前提**：等級分調得不夠本身就會使連勝連敗多於期望（`docs/results/rating-filter.md`）；Lichess arena 是隨機配對，系統無從依狀態挑對手，報告須先寫明這個不需要任何操控的解釋
- **輸出**：`docs/results/streaks.md`

| 定位 | 方法 |

| 描述 | Brier 分數的 Murphy 分解（可靠度、解析度、不確定度），比較系統的期望勝率、主基準與依狀態調整的勝率 |

- **資料**：Lichess 2014 年下半年的 arena；OGS 2023 年；AoE2 2026 年 6 月 24 日之後

### 跨遊戲的預測驗證（主要交付）

Lichess 的隨機配對提供因果識別，但不是電競式的排隊配對。第二、三份資料檢驗「期望勝率在哪些情況下錯」與「近況能否修正它」在其他配對機制下是否仍成立。候選、欄位與授權見 `docs/data/other-data.md`。

| 資料 | 配對機制 | 系統的期望勝率 |
|---|---|---|
| OGS 圍棋 | 自動配對與自選挑戰混合，資料分不開；有讓子棋 | 表頭沒有對局前等級分，依 OGS 公開的等級分程式（`online-go/goratings`）重放，讓子依其規則換算 |
| AoE2（aoe2-guide 的快照） | 系統排隊配對，1v1 | 對局前等級分 `old_rating`，以 Elo 公式換算 |

| 定位 | 方法 |
|---|---|
| 主要做法 | 沿用 Lichess 定下的做法：系統期望勝率的校準迴歸；主基準 offset 的模型依序加入上一局結果、上一局等級分變動、對手的同一組近況，以時間切分的樣本外對數分數決定各項是否加入 |
| 既有成果 | 民間停止規則的回測保留，不再延伸 |

- **沿用的是方法，不是係數**：等級分的尺度與遊戲不同，Lichess 估得的係數不能直接套用；各資料在自己的估計段重估，在評估段評估
- **不做**：因果的 tilt 識別與 crossover。兩份資料的分差都不是隨機指派的，只能作外部效度，不能估計因果效果
- **與 Lichess 的差異須在報告說明**：AoE2 與 OGS 都沒有和局，有序模型退化為二元 logistic；沒有 rating deviation 時新手期另以累計局數界定；OGS 含機器人帳號與讓子棋，自選挑戰的對手不是系統指派的
- **資料來源**：OGS 已確認授權；AoE2 取自維護者不明、未寫授權條款的粉絲網站快照，使用者同意作外部效度的參考（`data/raw/aoe2/SOURCE.md`）
- **AoE2 的設計**：只有約一個月（2026 年 6 月 2 日至 7 月 3 日），6 月 24 日前估計、之後評估。序列有缺漏，「上一局」須上一場的 `new_rating` 等於本場的 `old_rating`，否則視為本日無上一局；兩者在本場開始前都已知。連勝連敗與停止規則只用一天內每一場都接得上的天。新手為局前累計局數（`career_wins` 與 `career_losses` 之和減一）未滿 30。沒有 RD，主基準去掉 RD 收縮項；只有 1v1 一個類別
- **輸出**：`docs/results/other-games.md`

### 不做的分析

| 分析 | 理由 |
|---|---|
| 前局效果的其餘對照：玩家隨機截距的 GLMM、Bradley–Terry–Davidson 模型、錦標賽之後大廳的下一局 | 已有多種對照且結論一致；再加一個不改變結論 |
| 固定長度組內的貝氏變點模型、risk-adjusted CUSUM | Blitz 的前局效果只延續一局，持續偏移的前提不成立 |
| 最適停止規則（動態規劃、one-stage look-ahead） | 停止規則暫停延伸，不列必要交付 |
| GAM、校準樣本上的重新校準 | 預測模型的候選項事先寫定，由樣本外表現決定是否加入；arena 的整體校正已依同一判準不保留 |
| 預測模型的 GAM 與玩家隨機截距 GLMM | 探索性試過（`scripts/explore/gam_glmm*`、`gam_decomp*`、`gam_in_project_family.py`），結論是不採用。GAM 在 Blitz 沒有改善；Bullet 有改善，但來自新手的 RD 校準（主基準的問題，不是近況），近況項的非線性只有很小的增益。GLMM 對訓練期見過的玩家增益極小，而下半年多數對局的玩家沒在上半年出現過，隨機截距只能取 0；Bullet 反而較差 |
| 第一局作為停止決策的探測 | 停止規則暫停延伸；首局與空檔時間的預測分析另列選做 |
| Romano–Wolf 的逐步檢定與 SPA 檢定 | 規則只有少數幾條，以 Holm 法校正即可 |
| 效果異質性的隨機斜率 GLMM | 玩家間的差異以各玩家斜率的變異數與排列檢定回答，不需要混合模型 |
| 輸後的 rematch | 與交付物無關 |
| 局序與表現的 pattern-mixture | 連續對局的最終長度由各局的結果決定，依長度分組以未來的結果為條件，前提不成立；停止規則的回測已回答對玩家有用的問題 |
| 競爭風險 hazard、對局長度的機械效果 | 只服務附錄，且須逐局取得 API 的對局時間 |
| 2014 年 pool 的可行性檢查 | 延伸，不在交付物內 |
| 區分 tilt 與濾波誤差 | 交付物只需要預測力；RD 的變化不足以區分，寫成限制 |

## 結論之間的依賴

### 會影響其他方法的結論

| 結論 | 由哪個方法得出 | 影響的方法 |
|---|---|---|
| 配對確為隨機 | 配對批次的重建 | 前局效果模型、續下的選擇、附錄 |
| 主基準 | 三個基準 | 幾乎所有方法：表現的基準、勝和負機率、連勝連敗的基準 |
| 前局效果的大小與形狀 | 前局效果模型 | 前瞻驗證的檢驗量 |
| 殘差能由近況預測 | 等級分是否失準 | 依狀態調整的勝率的候選變數；連勝連敗的解讀 |
| 2014 年的結論是否重現 | 前瞻驗證 | 停止規則的結論能否作為建議；修正後的勝率是否註明未通過驗證 |

### 各方法在結論成立與不成立時的走向

| 方法 | 依賴的結論 | 成立時 | 不成立時 |
|---|---|---|---|
| 依狀態調整的勝率 | 加入近況的項改善樣本外對數分數 | 加入該項 | 修正後的勝率即主基準本身 |
| 停止規則（既有成果） | 登記的回測與等效性判定 | 依既有登記陳述 | 區間未達等效性判準時寫成樣本不足以判斷 |
| 修正後勝率的標示 | 前瞻驗證通過 | 標明修正後的勝率經前瞻資料驗證 | 註明修正後的勝率未通過驗證 |
| 連勝連敗的檢定 | 依狀態調整的勝率校準 | 超額在它之下消失，即等級分調得不夠的結果 | 超額在它之下仍存在，報告為近況項未捕捉的序列相依 |

## 工作原則

- **術語**：方法以修課內容的組合陳述，不用文獻中的專名（`GLOSSARY.md`）
- **共用 module**：修正的概似比檢定在 `scripts/likelihood.py`；arena 的樣本、配對批次與主基準殘差在 `scripts/arena_batches.py`
- **帳號以整數代碼分組與串接**：`lichess_games.parquet` 的 `white_id`、`black_id` 與 `player_games.parquet` 的 `player`、`opponent` 是同一套代碼；帳號名稱只在與 API 資料串接時使用
- **一次只跑一個分析**：以 `systemd-run --user --scope -p MemoryMax=20G -p MemorySwapMax=0` 加上執行緒數的環境變數限制（`docs/internal/computing.md`）
- **新假設的驗證**：已用資料可探索；確認性資料動用前先另立登記，保留既有前瞻驗證文件
