# 報告用詞與方法說明

適用於 `report/` 的書面報告、投影片及講稿。簡報的句型與版面另見 `docs/internal/slides.md`；個別術語的定義見根目錄 `GLOSSARY.md`。

## 讀者與首次說明

讀者是統計研究所師生。數理統計、迴歸與 likelihood 可作為起點；不要因方法出現在引用論文中，就假設讀者已學過。迴歸以外的方法首次出現時，先用已知概念說明它解決什麼問題，再給名稱和公式。模擬可從 MC 的「重複生成資料並重估」說起。

本報告假設聽眾已熟悉 AIC、BIC 與 LRT。直接說明採用的準則及必要修正，不重講基本定義；是否比較不同準則，依研究問題決定，不為展示方法另加一頁。

玩家 intercept/slope 模型先從 MLR 中共用係數的限制說起：允許每位玩家有自己的 intercept 和上一局結果 coefficient，再以共同 Normal distribution 描述這些係數。用資料少時向共同平均收縮說明 partial pooling，交代 prior、posterior 與未見玩家的預測，不假設讀者熟悉 Bayesian 模型。兩頁內說清模型與估計，明示原論文 binary 模型和本題雙方 ordinal 延伸的差異。簡報與口稿不介紹 spline 或 knots。

多數方法是 GLM、概似比或 score 檢定、重抽樣（permutation、bootstrap）的特例或組合，從這些已知方法講起，不另立名詞：calibration regression 講成以預測的 logit 為 predictor 的 logistic regression，Bradley–Terry 講成每位玩家一個參數的 logistic regression，Cochran–Mantel–Haenszel 講成每批一個截距的 score 檢定。文獻上的專名只在需要出處時放在該段最後一句。

Lichess 欄位或西洋棋術語首次出現時說明其意義，定義以 `GLOSSARY.md` 為準。對局用時首次列出短、中、長與原始類別的對照，後續口稿使用中文簡稱；圖表用 Short、Medium、Long。不同遊戲各自說明分類，不把「用時」稱為「賽制」。

統計方法、評估指標與推論術語使用英文原名，簡報標題、內文、圖表與口稿一致，例如 log loss、score MSE、ordinal logistic regression、interaction、random slope、calibration、confidence interval（CI）。首次出現的縮寫先給全名；已假設熟悉的 AIC、BIC、LRT 可直接使用。一般敘述與對局用語維持中文，例如評分、上一局、短中長用時；不逐字英譯整句。英文名稱不等於讀者已懂，陌生方法仍用中文說明用途，不另造方法名。

## 每個方法的講述順序

簡報依研究問題組織，方法說明服務模型取捨與研究結論。

1. 先說要解決的預測問題，以及評分基準仍缺少的資訊。
2. 說明方法如何使用局前資料、主要假設與比較對象；非基礎方法先從熟悉的迴歸或機率模型說起。
3. 展示實驗結果，交代保留、不採用或尚待共同比較的理由。文獻對應具體做法，不必按單篇論文順序重述整份研究。

每個方法標明主要模型、替代模型或適用範圍診斷。已完成的探索與正式共同流程分開介紹；結尾交代模型、結論及適用範圍，未完成的定案比較須如實標示。每頁以問題或方法名稱標示位置，不編號。

術語、符號與縮寫在首次出現的那一頁定義；同一個量全篇只用一個名稱與一個符號。同一步超過五頁時，加次一層的路標，並以同一個數字例子貫穿各頁的公式。

文獻引用須對應一項具體做法；「提供依據」「借用思路」後面要寫出所依據或借用的是哪一步。

## 用詞檢查

- 寫出關係的兩端及其作用。若使用「連結」「支持」「可比」等詞，讀者應能看出哪些對象、資料或參數透過什麼條件產生關係。
- 保留會改變統計解讀的區別，例如期望得分與真實實力、表現低於期望與表現衰退。刪除只重述前句的對比或結語。
- 用日常的詞。「同儕」這類書面而生硬的詞改成「其他玩家」「比較對象」；白話說得清楚時不用較文的說法。
- 使用通行的統計術語；研究對象、樣本條件和模型差異則直接描述。不得為縮短文字自造名詞或縮稱，也不以替自造詞補定義的方式保留它。
- 先用一句話說明術語的用途，再檢查是否仍需要該術語。投影片正文看不懂時，不能只把定義移到講者註解。

| 避免的說法 | 依實際意思改寫 |
|---|---|
| 主分析、主模型 | 指明資料或模型，例如「前面用 Lichess 錦標賽資料建立的預測模型」 |
| 玩家局、玩家局數 | 一位玩家在一局中的紀錄、觀測筆數；說明同一對局可能留下雙方各一筆 |
| 有同場上一局 | 資料中找得到該玩家在同一場錦標賽裡更早的對局紀錄 |
| 缺歷史 | 找不到先前對局紀錄；交代是限同一場錦標賽，還是所有紀錄都找不到 |
| 簡單近況、RD 延伸 | 加入上一局資訊的模型、允許玩家係數不同的模型 |
| 和局帶寬 | 兩個累積機率 cutpoint 的距離 |

替換用詞後重寫整句，避免機械替換造成重複、語意不通或範圍改變。「在這場錦標賽首次出現在資料中」不一定是玩家實際參加的第一局；缺少紀錄也不等於沒有下過棋。口語化時仍須保留這些差別。

## 口稿的口述風格

口稿寫成報告者可以直接說出口的句子，保留主詞、動作與比較對象。可用「我們」「這一局」「左圖」，長句依意思拆開；不要為顯得口語而加入無內容的問答、過場或語助詞。

禁止無效的名言格式：空泛金句、格言式對仗、假深刻的比喻，以及只替前文加重語氣的獨立收尾句。直接說明這份資料的結果。例如刪去「訓練內的選擇不能代替後續測試」，改述「玩家差異模型在中用時的預測誤差較低，短用時的 score MSE 卻增加」。一頁沒有新增結論，就不另加結語。

「不是……而是……」「不代表……」只用於釐清會影響解讀的差異，例如預測與因果、觀測筆數與對局數。刪除無人提出的反駁，以及只重述前句的對比。不要用引言區塊、粗體或破折號把普通敘述包成金句。

精簡文字時保留樣本條件、比較基準、不利結果與推論限制；公式、模型設定及資料來源不因口語化而改變。數理統計與迴歸的通行術語可以直接使用，不必把每個術語都換成長篇白話。

## 修改後的核對

核對報告、口稿、圖表標籤及詞彙表的相應位置，確認投影片與口稿逐頁對應。通讀每個改動段落，檢查能否一口氣說清楚誰、用什麼資料、和什麼比較，以及結果如何；再檢查有無自造縮稱、重複用字或無資訊的收尾。編譯通過不能代替文字審閱。Typst 編譯與溢頁檢查依 `CLAUDE.md`；只有使用者要求拍板版面時，才將 PDF 轉成圖片檢視。
