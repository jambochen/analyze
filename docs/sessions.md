# 連續對局、續下與離開的操作定義

所有以「離開」為反應變數的方法（隨機配對下匹配品質的效果、EOMM 關鍵假設的檢驗、Heliyon 模型的比較、改制的交叉驗證、表現衰退的選擇模型）都以本文件的定義為基礎。腳本為 `scripts/sessions.py`，產出 `data/processed/player_games.parquet` 與 `outputs/tables/sessions_*.csv`、`outputs/figures/sessions_*.png`。

## 分析單位：玩家局

每局拆成雙方各一列。每位玩家的對局依開局時間排成一條序列，所有定義都在這條序列上計算。

- **排除無鐘對局**：無鐘對局一局可跨數日，開局時間不代表玩家當時在線，放進序列會把同一段時間內的即時對局切開。無鐘對局包括通信棋，以及 2014 年 12 月以前計入 Classical 等級分的無鐘對局（`docs/speed-class.md`），局數都很少（`sessions_sample.csv` 的 `correspondence`、`no_clock_classical`）
- **排除自己對自己的局**：同一帳號同時是白方與黑方，無法拆成兩名玩家（`self_games`）
- **類別與跨類別**：類別一律用對局當時等級分所屬的速度類別（`speed`，`docs/speed-class.md`），不用月檔 `Event` 的時間類別。跨類別不切開：同一玩家從 Blitz 換到 Bullet，仍是同一次坐在電腦前。序列包含 Bullet、Blitz、Classical 三類，連續對局可跨類別。在主門檻下，連續對局內換類別的轉換只占少數，Classical 之後換類別的比例最高（`sessions_cross_class.csv`）
- **2013 年只作前文**：2014 年 1 月初的對局，其局序與連續對局編號須接上 2013 年 12 月的對局，否則會把延續中的連續對局切斷。序列從 2013 年 1 月起計算，輸出只保留 2014-01-01 00:00 UTC 至資料終點的玩家局

時間計算一律用 UTC 的開局時間。月檔依巴黎時間切月（`month` 欄不是 UTC 月份），2015 年 6 月月檔止於 2015-06-30 22:00 UTC，此即資料終點；之後的對局在未下載的 2015 年 7 月月檔。

## 連續對局的切分門檻

### 開局間隔的分布

只有開局時間，沒有結束時間，因此相鄰兩局的開局間隔包含前一局本身的長度。間隔的對數分布（`sessions_gap.png` 上排）在三個速度類別都有兩個主要結構：

- **第一個峰**：位置隨速度類別的對局長度移動，Bullet 最左、Classical 最右。這是「下完立刻再開一局」的間隔，峰的位置即一局的典型長度加上找對手的時間
- **右側的長尾與日週期**：峰之後密度緩慢下降，在約一天處有第二個峰（隔天同一時段再來），其後還有以天為間隔的小峰

兩者之間沒有清楚的低谷。對數密度在第一個峰之後一路下降，最低點落在數小時處（`sessions_threshold_fit.csv` 的 `valley`），那是日週期的低谷（睡眠），不是一次連續對局的結束。因此「分布的低谷」不適合作為門檻，改用混合分布的分界。

### 兩成分混合分布

以對數開局間隔擬合兩成分 Gaussian mixture（在直方圖上做 EM），門檻取第一成分後驗機率降到 0.5 之處。

- **樣本**：2014-01-01 起、開局後 30 天仍在資料內的玩家局，且 30 天內有下一局。限制在開局後 30 天完整可見，避免期末截斷壓低長間隔的密度
- **依前一局的速度類別分開擬合**：間隔包含前一局的長度，故以前一局的類別歸類
- **主門檻**：合併 arena 與一般對局、擬合範圍最寬（30 天）的分界，取整到分鐘（`sessions_threshold.csv` 的 `threshold_seconds`）。前一局屬哪一類，就用哪一類的門檻判斷下一局是否屬同一段連續對局

第一成分只描述第一個峰，第二成分吸收其後的長尾與日週期，兩成分都不是嚴格的 Gaussian。分界因此依賴擬合範圍：把範圍縮到 1 天或 6 小時，第二成分往左移，分界隨之變小（`sessions_threshold_fit.csv` 的 `fit_upper_seconds`）。arena 對局的分界比一般對局小，因為錦標賽中配對由系統即時進行，下一局的間隔集中在一局長度附近（`source` 欄）。這些差異是選擇主門檻後必須做敏感度分析的理由。

### 開局間隔與「間隔減去對局長度」

以每方 40 步、時鐘用盡估計一局的名目長度 $D = 2(\text{base} + 40 \times \text{increment})$。這只是長度的估計，與速度類別的判定無關：研究期間大部分時候 Lichess 以 base + 30 × increment 劃分速度類別（`docs/speed-class.md`）。直接相減的「間隔減去 $D$」不可用：實際對局多半短於名目長度，相當比例的相鄰間隔小於 $D$，相減後取不了對數，擬合結果隨截斷方式大幅改變。

改看間隔除以 $D$ 的比值（`sessions_gap.png` 下排）。比值的第一個峰在三類別都落在 1 或略低於 1，表示扣除對局長度後，三個類別的連續對局有相近的結構。以此擬合的分界（`sessions_threshold.csv` 的 `ratio_threshold`）構成另一種門檻規則「間隔不超過 $k \cdot D$」，納入敏感度比較。

主門檻採固定秒數而不採比值規則，理由是與文獻的切分方式可比，且兩者在各類別的續下率幾乎相同（`sessions_sensitivity_seq.csv` 的 `main` 與 `ratio`）。比值規則的優點是能處理 Classical 內部時間制差距很大的問題，見限制。

### 與 arXiv 2503.21713 的比較

該文以 Bullet 5 分鐘、Blitz 7 分鐘切分。本資料的主門檻較長，Blitz 的差距尤其大：7 分鐘落在 Blitz 開局間隔的第一個峰上（`sessions_gap.png` 的灰色虛線），會把正在連續下棋的玩家在一局 5+0 下完之前就判為離開。原因很可能是口徑不同：若該文的間隔是從上一局結束起算，就不含對局長度，而本資料只有開局時間。文獻門檻因此不直接套用，只作為敏感度比較的一種規則（Classical 該文未給，以主門檻代入）。

## 反應變數

所有時間窗皆從本局的開局時間起算。時間窗延伸超過資料終點的玩家局，無論之後是否已觀察到下一局，一律記為缺值：若只把「已觀察到下一局」的留下，期末的離開率會偏低，且各期的定義不一致。

| 欄位 | 定義 | 可用的開局時間上限 |
|---|---|---|
| `continue_session` | 下一局的開局間隔不超過主門檻（依本局類別），即同一段連續對局內還有下一局 | 資料終點減主門檻 |
| `leave_8h` | 之後 8 小時內沒有下一局（EOMM 的定義） | 資料終點減 8 小時 |
| `churn_14d` | 之後 14 天內沒有下一局（Heliyon 2024 的定義） | 資料終點減 14 天 |
| `tour_left` | arena 對局：同一場錦標賽內沒有下一局，且本局之後錦標賽仍有足夠時間 | 見下 |
| `return_seconds`、`return_censored` | 到下一局的秒數；沒有下一局者以到資料終點的秒數記，並標為右設限 | 不受限 |

「之後是否還有對局」計入三個速度類別的所有對局，不分 arena 或一般對局，也不分速度類別。EOMM 原定義只看 1v1 的同一模式，西洋棋全為 1v1；換速度類別仍是留在平台上。

8 小時與 14 天從開局起算，含本局的長度。對 Bullet 與 Blitz，這段長度相對於時間窗可忽略；長時制的 Classical 一局可達數十分鐘以上，8 小時的實際離開時間窗略短。

### 可用的樣本期間

2014 年的對局全部可用 2015 年的資料判定，14 天的時間窗在 2014 年內完全不受期末影響。2015 年的對局，`churn_14d` 只定義到資料終點前 14 天、`leave_8h` 到前 8 小時、`continue_session` 到前一個主門檻。實際的最後一個有定義的開局時間與非缺值筆數見 `sessions_sample.csv` 的 `*_last_start` 與 `*_n`。2015 年 4 月 21 日的改制之後仍有約兩個月的對局可判定 14 天流失，足以支援改制前後的比較。

### 錦標賽中途離開

錦標賽有固定時長，玩家可在賽中途離開，也可下到結束；兩者須分開。錦標賽的時長由該場第一局與最後一局的開局時間推算。

- **錦標賽的時長**：第一局到最後一局的時距集中在數個以 5 分鐘為單位的固定時長附近，從半小時到兩小時（`sessions_tournament_span.png`、`sessions_tournament_span.csv`），與 arena 以固定分鐘數設定時長相符。名目時長不在資料中，只能由這些集中處推斷。也有不少場次的時距很短，這些場次的參賽人數很少（`median_players`），多半是人數不足而提早無人可配
- **風險集**：本局開局後經過一局的名目長度 $D$，該場錦標賽仍有新局開出（最後一局的開局時間減本局開局時間不小於 $D$）。滿足者才有機會再下，才可能「中途離開」；不滿足者屬於下到錦標賽結束，記為缺值。風險集只依錦標賽的時程而定，不依本局之後是否續下，故不因結果而選樣
- **期末截斷**：錦標賽最長約 2 小時，最後一局在資料終點前 2 小時內開出的場次可能被截斷，其對局記為缺值
- **賽後是否回來**：錦標賽的最後一局（`tour_last_game` 為真）之後的 `leave_8h`、`churn_14d`，即「賽後不再回來」

錦標賽的實際結束時間晚於最後一局的開局時間，以最後一局推算偏保守：會把少數其實仍有時間再下的局排除出風險集，但不會把下到結束的局誤判為中途離開。風險集的邊界改為 $0.5D$、$2D$、$3D$ 時，邊界越小（納入越接近結束的局），中途離開率越高，但輸、和、贏之間的大小順序不變（`sessions_tour_margin.csv`）。

### 伺服器停擺

全站 10 分鐘以上沒有任何新局的時段視為伺服器停擺（`sessions_outages.csv`），最長的一次持續數小時。停擺時的「沒有下一局」不是玩家的選擇。`to_outage` 欄記錄本局開局到下一次停擺的秒數，後續分析可據以排除時間窗內遇到停擺的玩家局；受影響的筆數見 `sessions_sample.csv` 的 `outage_in_session_window` 與 `outage_in_8h`，占全體的比例很小。

## 描述與敏感度

### 主定義下的描述

`sessions_rates.csv` 依速度類別、arena 或一般對局、本局結果列出各反應變數的比率與非缺值筆數；`sessions_rates_month.csv` 依月份列出。

- **速度類別**：一般對局中，續下率 Bullet 最高、Classical 最低，8 小時離開率與 14 天流失率的順序相反
- **arena 與一般對局**：arena 對局的續下率高於一般對局、8 小時離開率較低，在三個速度類別都如此。錦標賽有固定時長、配對由系統即時進行，續下的意義與大廳不同，兩者的差距不可直接解讀為配對方式的效果
- **本局結果**：輸棋後的續下率低於贏棋後，8 小時離開率、14 天流失率與錦標賽中途離開率都是輸棋後最高。這個差距在 arena 比在一般對局大
- **時間趨勢**：一般對局的各比率在整段期間平穩；arena 的續下率逐月上升、離開率下降，2015 年 4 月以後更明顯。改制的交叉驗證須處理這個改制前已存在的趨勢

14 天流失率以玩家局為單位，數值很低：活躍玩家貢獻大部分的對局，而其中只有一局是「最後一局」。Heliyon 2024 以玩家日為單位，兩者不可直接比較；需要玩家日的分析須自行彙總。

### 門檻的敏感度

續下率在門檻 1 分鐘到 2 小時之間的變化見 `sessions_sensitivity.csv`、`sessions_sensitivity.png`（固定門檻與比值門檻兩組），依局序的續下率在五種規則下的比較見 `sessions_sensitivity_seq.csv`、`sessions_seq.png`。五種規則為主門檻、主門檻的一半與兩倍、文獻門檻、比值門檻。

- **續下率的水準隨門檻而變**：門檻短於一局的典型長度時，續下率接近零；越過第一個峰後快速上升，之後緩慢上升而不飽和。續下率的絕對值因此沒有門檻之外的意義，報告時須附門檻
- **輸贏的差距方向不受門檻影響**：只要門檻越過第一個峰，輸棋後的續下率在每個門檻、每個速度類別、arena 與一般對局都低於贏棋後。門檻在主門檻的一半到兩倍之間時，差距的大小變化有限
- **門檻短於對局長度時會出現假象**：門檻只有一、兩分鐘時，被判為續下的是下得很快就結束的局（早早認輸、斷線），輸贏的比較反映對局長度而非續下意願。文獻門檻在 Blitz 正落在這個區間，是不直接沿用文獻門檻的另一個理由
- **和局的位置對門檻敏感**：和局通常下得較久，短門檻下和局後的續下率偏低。Classical 一般對局中，和局與輸棋的續下率在主門檻附近交叉，兩者孰高孰低取決於門檻。涉及和局的比較須在多個門檻下檢查
- **arena 高於一般對局**：在所有門檻下都成立
- **速度類別的順序**：一般對局在固定的分鐘門檻下，Bullet 的續下率始終最高；各類別用各自的主門檻時順序相同
- **局序的走勢**：一般對局中，續下率隨局序上升，五種規則皆然。這是選擇的結果：能下到後段局序的，多半是本來就連續下很多局的玩家。arena 的走勢較平，局序後段受錦標賽時長截斷。這正是表現衰退分析必須為續下建模的原因（`CLAUDE.md` 的硬性紀律），不可把局序的走勢解讀為疲勞或投入

結論：門檻的選擇改變續下率的水準與連續對局的長度分布，但不改變上述描述結論的方向，和局的相對位置除外。後續以離開為反應變數的分析，應以主門檻為主，至少以主門檻的一半與兩倍重做主要估計；8 小時與 14 天兩個定義不依賴門檻，可直接並列。

## player_games.parquet

每列為一個玩家局，範圍為 2014-01-01 00:00 UTC 至 2015-06-30 22:00 UTC，不含無鐘對局與自己對自己的局。筆數與玩家數見 `sessions_sample.csv` 的 `n`、`players`。檔案依玩家代碼除以 16 的餘數分桶寫入，桶內依玩家、開局時間排序；需要全域時間順序者須自行排序。

| 欄位 | 型別 | 說明 |
|---|---|---|
| `game_id` | str | 對局 ID，每局兩列 |
| `player` | uint32 | 帳號代碼，即 `lichess_games.parquet` 的 `white_id`、`black_id`；帳號名稱須經該檔對回 |
| `opponent` | uint32 | 對手的帳號代碼 |
| `color` | str | `white` 或 `black` |
| `start` | datetime (UTC) | 開局時間，到秒 |
| `speed` | str | Bullet、Blitz、Classical：對局當時等級分所屬的速度類別（`docs/speed-class.md`），`elo`、`opp_elo` 即此類別的等級分 |
| `time_control`、`base_seconds`、`increment_seconds` | str、int | 時間制 |
| `est_duration` | int | 名目對局長度 $2(\text{base} + 40 \times \text{increment})$，秒 |
| `tournament_id` | str | 錦標賽 ID，一般對局為 null |
| `arena` | bool | 是否為 arena 錦標賽對局（2014 年起錦標賽全為 arena） |
| `elo`、`opp_elo` | int | 自己與對手的對局前等級分（表頭的 `WhiteElo`、`BlackElo`）；極少數缺值 |
| `score` | float | 本局得分，自身視角，勝 1、和 0.5、負 0 |
| `result` | str | `win`、`draw`、`loss` |
| `player_game_no` | int | 自 2013 年 1 月起該玩家的累計局數（不含無鐘對局）；2013 年以前的對局史不在資料中，屬左截斷 |
| `session_no` | int | 自 2013 年 1 月起該玩家的連續對局序號（主門檻）；`player` 與 `session_no` 合為連續對局的鍵 |
| `game_seq` | int | 局序，連續對局內的第幾局，第一局為 1 |
| `session_games` | int | 所屬連續對局的總局數 |
| `session_threshold` | float | 本局適用的主門檻，秒 |
| `prev_gap` | int | 距上一局開局的秒數；該玩家的第一局為 null |
| `continue_session` | bool | 續下；時間窗超出資料終點者為 null |
| `leave_8h` | bool | 8 小時內沒有下一局；同上 |
| `churn_14d` | bool | 14 天內沒有下一局；同上 |
| `tour_last_game` | bool | 是否為本人在該場錦標賽的最後一局；一般對局為 null |
| `tour_left` | bool | 錦標賽中途離開；不在風險集或可能被截斷者為 null |
| `tour_first`、`tour_last` | datetime (UTC) | 該場錦標賽第一局與最後一局的開局時間 |
| `return_seconds` | int | 到下一局的秒數，或到資料終點的秒數 |
| `return_censored` | bool | 是否右設限（資料終點前沒有下一局）；每位玩家恰有一列為真 |
| `to_outage` | int | 到下一次全站停擺開始的秒數 |

不含 `WhiteRatingDiff`、`BlackRatingDiff`：兩者是本局結果的函數，依硬性紀律不作預測或基準之用。不含配對來源（`source`），大廳對局與指定邀戰須另以 API 的結果串接。

## 限制與未解決的疑點

- **沒有結束時間**：開局間隔包含前一局的長度，連續對局的判斷混入對局長短。一局拖很久與下完後休息一陣子無法區分。名目長度只是時鐘的上界估計，步數多時仍可能超過
- **Classical 的時間制差距大**：Classical 從 10 分鐘到數小時都有，固定秒數的主門檻對長時制偏嚴，一局本身就可能超過門檻。有一部分 Classical 對局的名目長度超過主門檻，這些對局之後的續下可能被低估。比值規則可處理此問題，其續下率在 Classical 與主門檻相近，但個別長時制對局的歸屬不同；長時制占比高的分析應改用比值規則重做
- **混合分布的分界依擬合範圍而變**：第二成分不是 Gaussian，分界是一個慣例而非資料中的自然斷點。這是必須做門檻敏感度分析的根本原因
- **同時在多個對局**：即時對局一次只能下一局，但無鐘對局已排除，若玩家同時下通信棋，其在線狀態不反映在序列中
- **配對來源未分**：一般對局包含大廳對局與指定邀戰，熟人邀戰的續下行為可能不同；2014 年 6 月至 10 月疑似 pool 對局的局也混在一般對局中。待 API 的 `source` 串接後須分開描述
- **錦標賽的結束時間是推算的**：以最後一局的開局時間代替，名目時長不在資料中。參賽人數少的場次可能因無人可配而提早結束，此時「沒有下一局」不是玩家的選擇，風險集條件只能排除一部分；以參賽人數分層的敏感度分析待做
- **跨帳號**：同一人換帳號、多帳號時，流失與回訪都會被高估，資料無法辨識
- **停擺只標記不排除**：停擺時段的玩家局保留在資料中，由後續分析決定是否排除
