# 分析方向的比較

本資料可做、且與等級分匹配機制相關的分析方向，依四個角度排名。各方向的文獻出處見 `docs/literature.md`。

## 方向

| 代號 | 方向 | 和匹配機制的關係 | 統計模型 | 識別與推論 | 本研究所需資料 | 對應文獻 | 文獻資料是否公開 |
|---|---|---|---|---|---|---|---|
| A | 期望得分的校準（含和局、先手） | 匹配系統以期望勝率判斷配對是否公平，期望勝率不準，公平配對就不公平 | 勝、和、負的有序結果模型；考慮和局與先手的配對比較模型 | 校準曲線、概似比檢定、proper scoring rule | Lichess 月檔表頭（分差、等級、顏色、時間制、結果） | 2505.24783、2506.11354、1910.06081、2607.25655 | 2607.25655 用 Lichess 公開月檔；2505.24783 用 US Chess 網站公布的賽果，彙整後的資料未說明是否公開；2506.11354 由 ICCF 提供，未說明是否公開；1910.06081 用英超賽果，未寫來源 |
| B | 匹配品質對留存的效果 | 直接回答「配得越準，玩家是否越願意留下」，即 EOMM 的核心假設 | 一局後是否離開用 logistic 迴歸；回訪時間用離散時間 hazard 或 Cox 模型，處理右設限 | 2014 年 arena 錦標賽的隨機配對；randomization inference；以錦標賽與配對時刻分層，玩家層 cluster 穩健標準誤 | Lichess 月檔表頭；以 API `source` 區分 arena 與瑞士制、排除大廳中的指定邀戰；大廳對局作自選對手的對照 | 1702.06820、2209.03950、Heliyon 2024、1701.02359、1709.06737 | 皆不可取得或無資料：EOMM 為 EA 內部資料；Heliyon 2024 為 Netmarble 伺服器紀錄，論文明寫不公開；2209.03950 為理論論文；1701.02359、1709.06737 用開發中的手遊 Hipster Sheep，未說明是否公開 |
| C | 連勝連敗是否超出等級分的預期 | 電競玩家常指控系統故意製造連敗，須以等級分預期為基準判斷連敗是否異常 | 依每局期望機率模擬結果序列，做 parametric bootstrap | 以等級分預期為虛無模型，取代打亂時間順序 | Lichess 月檔表頭 | 2207.07780、2503.11669、2409.06739、Activision 白皮書 | 2207.07780 用 Lichess 公開月檔，程式碼在 GitHub；2503.11669 為數值計算，無資料；2409.06739 用公開的連勝紀錄；Activision 白皮書為內部資料 |
| D | 連續對局的表現衰退 | 連敗後表現若低於期望，系統對該狀態的玩家高估了期望勝率，可據此調整配對 | 表現殘差或三類結果的混合效應模型，含局序與上一局結果 | 續下的選擇偏誤以 inverse probability weighting、玩家內比較、敏感度分析處理 | Lichess 月檔表頭 | 2503.21713、FDG 2024 LoL 連勝研究 | 2503.21713 爬取 Lichess，論文稱資料與程式碼在作者 GitHub，網址未查得；FDG 2024 收集 LoL 頂尖玩家的對局，來源與是否公開未查證 |
| E | 等級分系統的預測力比較 | 比較作為配對依據的 Elo、Glicko-2 哪個預測較準 | 重算 Elo 與 Glicko-2 並調整參數 | 時間序上的交叉驗證、proper scoring rule | Lichess 月檔表頭（結果序列） | 2410.02831、2512.18013、2104.14012 | 2410.02831 爬取 HLTV，論文稱資料隨 skillbench 程式碼公開；2512.18013 用 Games24x7 的 Ludo 資料，未說明是否公開；2104.14012 用 NHL、英超、NFL 賽果，未寫來源 |
| F | 新手期的等級分誤差 | 對應電競定級賽與冷啟動：新帳號的配對品質最差 | 期望得分殘差隨帳號累計局數的變化 | 以累計局數界定新手期，做敏感度分析 | Lichess 月檔表頭 | 2208.07704 | 2208.07704 用騰訊未具名的手遊 MOBA，不公開 |
| G | 非遞移性 | 單一數值的等級分無法表示相剋關係，匹配可能系統性失準 | 勝負循環結構的分解 | 統計推論架構不明確 | Lichess 月檔表頭 | 2110.11737、2502.03998 | 2110.11737 用 Lichess 抽樣與 FICS，公開；2502.03998 用 aoestats 的 AoE2 與 HSReplay 的 Hearthstone，稱為公開資料集 |
| H | 瑞士制的顏色公平性 | 錦標賽配對規則造成的系統性不公平 | 得分對多一局白棋的迴歸 | 2014 年瑞士制對局少，顏色分配規則未查清 | Lichess 月檔表頭；以 API `source` 區分瑞士制 | 2410.19333 | 2410.19333 用 28 場頂級賽事，未寫來源；頂級賽事的棋譜一般公開 |

「本研究所需資料」指在 Lichess 上做該方向所需的資料，皆可取得，取得難易見「資料可取得性」。「文獻資料是否公開」指對應文獻本身所用的資料；未說明者為論文未寫明，引用或複製前須再核對。B 的對應文獻皆無法以原資料複製，只能在 Lichess 上複製其方法。

## 分析完整性

標準：能否從問題、識別、模型、假設檢驗一路走到可行的建議。

| 排名 | 方向 | 理由 |
|---|---|---|
| 1 | B | 有問題、有隨機配對可識別、有模型與推論，最後能給系統端的配對建議。限制是錦標賽情境的外部效度 |
| 2 | A | 論證完整，但單獨做只是前置檢驗，建議只到期望得分該如何修正 |
| 3 | D | 能產出停止規則，但結論受選擇偏誤的處理方式左右 |
| 4 | C | 檢驗乾淨，但結論是描述性的（連勝是否異常），沒有直接的建議 |
| 5 | E | 評估完整，但建議停在該用哪個系統，Lichess 不會因此改系統 |
| 6 | F | 附屬分析，撐不起獨立的論證 |
| 7 | H | 樣本少，顏色分配規則未查清，論證缺一環 |
| 8 | G | 缺少明確的推論架構 |

## 資料可取得性

標準：手上的資料能否直接做，還要補什麼。

| 排名 | 方向 | 理由 |
|---|---|---|
| 1（並列） | A、C、D | 只要表頭，已下載 |
| 4 | B | 核心分析用已下載月檔中的錦標賽對局。arena 與瑞士制在 `Event` 都標為 tournament，須以 API 區分，但每場錦標賽查一局即可，請求量很小；開賽時間的結構也可交叉檢查。大廳對照組排除邀戰須逐局查詢，可先以敏感度分析代替 |
| 5 | G | 只要表頭，但需要足夠多的三人循環，對手組合可能過於稀疏 |
| 6（並列） | E、F | 2014 年以前建立的帳號，之前的對局史看不到（左截斷）：重算等級分須預熱，新手期也算不出累計局數。下載 2013 年的資料可補 |
| 8 | H | 須以 API 區分瑞士制，顏色分配規則還要查原始碼 |

## 統計模型的應用

標準：方法是否豐富、適用，假設能否在本資料上檢驗。

| 排名 | 方向 | 理由 |
|---|---|---|
| 1 | B | logistic 迴歸、存活分析（處理右設限）、randomization inference、cluster 穩健標準誤。識別靠已知的隨機機制，不依賴模型設對 |
| 2 | A | 有序結果模型、配對比較模型、概似比檢定、proper scoring rule，假設皆可直接檢驗 |
| 3 | D | 混合效應模型、inverse probability weighting、敏感度分析。方法豐富，但選擇偏誤的假設難以檢驗 |
| 4 | C | parametric bootstrap，方法單一但推論清楚 |
| 5 | F | 殘差趨勢與敏感度分析 |
| 6 | E | 偏重演算法調參與交叉驗證，推論成分少 |
| 7 | H | 單一迴歸 |
| 8 | G | 偏賽局論的分解 |

## 與 Elo、電競的貼近程度

| 排名 | 方向 | 理由 |
|---|---|---|
| 1 | B | 即 EOMM 的核心問題。錦標賽由系統配對、玩家無法挑選，最接近電競 |
| 2 | A | 匹配系統以期望勝率判斷公平，期望不準就配不公平 |
| 3 | E | 直接比較 Elo 與 Glicko-2，對應 CS:GO 的等級分系統比較研究 |
| 4 | C | 對應電競玩家「系統故意製造連敗」的指控，與 Activision 白皮書的連敗機率基準 |
| 5 | D | 對應 LoL 的 tilt 研究，結論可轉為依玩家狀態調整配對 |
| 6 | F | 對應電競的定級賽與冷啟動 |
| 7 | G | 對應電競的角色相剋，但西洋棋沒有角色選擇 |
| 8 | H | 瑞士制是錦標賽賽制，電競天梯不用 |
