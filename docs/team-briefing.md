# 一、四個提議的資料集

四份都下載跑過，結論是都不建議採用，理由各不相同。

## EV 電池健康

https://www.kaggle.com/datasets/srisyra02/ev-battery-health-prediction-dataset-20k

> notebook：`EV 電池健康` 節

合成資料，而且合成規則可以反推。

```
capacity_loss_percent + battery_health_percent   平均=100.0  標準差=0.0000000000
corr(state_of_health, battery_health_percent)    =  0.9898
corr(thermal_health_score, thermal_runaway_risk) = -0.9868
```

標準差 0，代表這兩欄恆等於 100，是同一個數字的兩種寫法。

缺失率也不對：70 欄裡 67 欄落在 3.05%–4.94% 的窄帶，剩下 3 欄剛好 0%。
真實感測器不會這樣缺，這是先造完整資料再按固定比例挖洞的特徵。

結果是好幾個「預測目標」其實是別的欄位算出來的。在這上面建模跑出來的
是合成程式的參數，不是電池行為。頁面也沒說資料來源。

## 臺北市實價登錄

https://www.kaggle.com/datasets/chrischien17/taiwan-taipei-city-real-estate-transaction-records

> notebook：`臺北市實價登錄` 節

加工過的二手版本，比內政部原始檔差。

時間跨度名義上 1986–2020，實際上 2019 年佔 93.3%，加上 2020 年共 98.3%，
剩下 8 個年度合計 103 筆。

兩個欄位名稱與內容對不上：

```
building_age （叫屋齡）  範圍 1907–2020  ← 實際是西元年
complete_year（叫建成年）範圍 0–108      ← 實際是民國年
```

行政區英譯不一致（`Beitou`、`shihlin` 無 District，`Zhongshan Area` 用 Area），
`urban_land_use` 有 `Quotient`、`work` 這類機翻殘留，`main_use` 裡
`Other` 與 `Others` 並存。原始中文編碼已遺失。

要做房價建議直接取內政部原始檔。

另外房價這個方向本身也有問題：仲介與銀行手上的資訊遠多於公開實價登錄，
我們算不出他們不知道的事。

## AI 對就業薪資

https://www.kaggle.com/datasets/debayank2024/ai-impact-on-jobs-and-salaries-2020-2026

> notebook：`AI 對就業薪資` 節、`復現第三方分析` 節

這份表面品質最好——71,913 列、17 欄、幾乎沒有 null、附了 data dictionary。
問題不在資料髒，而在**它不含回答自己標題所需的變數**。

**一、標題承諾的東西不在檔案裡。**

資料集叫 "AI Impact on Jobs and Salaries"，描述引用了 ILO 的生成式 AI
職業曝險指數。但 17 個欄位全部列出來，沒有任何一欄是曝險度：

```
work_year, experience_level, employment_type, job_title, salary,
salary_currency, salary_in_usd, employee_residence, remote_ratio,
company_location, company_size, experience_level_label,
employment_type_label, work_mode, salary_outlier_flag,
role_family, isco_group_hint
```

附的 data dictionary 其實沒有誤導，它寫 `isco_group_hint` 是
"for joining **against** AI-exposure data"——明指這是拿來**對外接合**的鍵，
ILO 那份是**待接合的外部來源**，不是已併入的欄位。誤導來自 Kaggle 的
標題與描述。

實際拿到的東西是 ai-jobs.net 的薪資表加兩個分類欄。要做 AI 曝險的題目，
得自己去 ILO 取指數再接，那這份資料就沒什麼加值了。

**二、就算接上曝險分數，也算不出「影響」。**

資料是職缺薪資的自我回報快照：沒有個人 ID（同一人跨年追蹤不了）、
沒有公司 ID、也沒有未受 AI 衝擊的對照組（全部都是 AI／資料類職缺）。

缺了這些，能做的上限是「曝險度不同的職業，薪資差多少」——那是橫斷面
關聯，不是「AI 造成了什麼」。而要回答前者，官方薪資調查的資料品質
遠比自願填報好。

**三、連橫斷面關聯都難算，因為跨年比較不成立。**

```
work_year   筆數     remote_ratio 均值
2020          75          62.0
2021         214          69.6
2022       1,114          58.5
2023       4,538          36.8
2024      27,690          22.5
2025      38,282          23.3
```

2024+2025 佔了 91.8%，標題寫的 2026 年一筆都沒有。

`remote_ratio` 那條曲線看起來完美呈現「疫情遠端高峰後回落」。但
2020–2021 合計才 289 筆，而且早期會去 ai-jobs.net 填報的人本來就偏向
遠端優先的新創。**樣本組成的變化和真實趨勢完全混在一起，分不開。**

### 這個問題有多難繞過：復現了票數最高的 notebook

https://www.kaggle.com/code/sasakitetsuya/ai-salaries-and-the-vanishing-middle

sasakitetsuya 的 *AI Salaries and the Vanishing Middle*。方法設計相當
用心——事前假說、自建可調整的職稱分類、OLS 控制年資／國家／公司規模／
工作型態、`bucket × year` 交互項、兩組敏感度分析，最後還誠實地否定了
自己原假說的兩條腿。

他獨立證實了第一點，notebook 裡直接寫 "the exposure columns are
**not present**"，所以整份分析只用薪資與職稱部分。

**但他的主結論仍然撐不住**，而且撞的正是第三點那面牆。

核心發現是「管理職 2023→2025 調整後薪資 +22%」。復現他的樣本後：

```
Management      2023  n=   140
People-facing   2023  n=    11
Middle          2023  n= 3,756
```

他在 caveat 裡承認了 People-facing 只有 11 筆，但沒提 Management 也才
140 筆——而 +22% 正是從這個基期算出來的。

更關鍵的是那一組裝的人換了：

```
2023 (n=140)  ：Data Manager 58、Head of Data 21、Data Analytics Manager 19
2025 (n=4,400)：Manager 2,238、Director 472、Data Manager 326
```

2023 年那組是「資料部門的主管」，2025 年主體變成泛用的 `Manager`／
`Director`，組內 Executive 比例也從 24.3% 掉到 13.3%。

**這不是同一群人薪水在漲，是這一組裝的人換了。** 他迴歸有控制年資，
但控不住職稱本身的語意在漂移。

一份做得這麼用心的分析還是撞上這面牆，說明樣本組成的問題不是分析技巧
能補救的——它是資料的性質。

## 1. 候選 I — 美國航班延誤 × 實測氣象

https://www.kaggle.com/datasets/arimancy/observed-weather-us-flights

> notebook：`候選 I` 節

**研究問題**：以實際觀測氣象為基準，哪些航空公司、機場與航線系統性地
少報天氣延誤？低報程度能否量化並排序，作為監理查核的優先順序？

| | |
|---|---|
| 上游 | US DOT BTS 準點紀錄 + NOAA ISD 氣象 + OurAirports 座標 |
| 筆數 | 4,280 萬筆航班，2019-01 至 2025-07 |
| 規模 | 完整版 6.1 GB；24 個月入門檔 1,406 萬列、1.1 GB，schema 相同 |
| 授權 | CC BY 4.0，上游 BTS 與 NOAA 為美國政府作品 |

DOT／FAA 是使用者，而 OIG 已認定 BTS 的延誤成因欄位不可信但沒給替代方法。
這份資料的機場對 NOAA 測站對照表，發布者說「不存在於任何維護中的公開資料」。
**掌握資料的航空公司沒有動機自己做這個分析**，這是這題的結構優勢。

欄位前綴設計是亮點：

```
wx        106 欄   航班資訊截止點「之前」的氣象，可安全使用
oracle     54 欄   航班自身事件時刻的氣象，用於預測即洩漏
reported    5 欄   航空公司自報的延誤成因，刻意保留但標明不可信
其他        46 欄   航班識別、日曆、壅塞度、前段航班
```

等於把洩漏風險寫進欄位命名。

關鍵賣點實測（入門檔，僅供篩選非分析結果）：

```
起點天氣    班次          平均抵達延誤   取消率
VFR      11,910,145        6.02 分      1.12%
MVFR      1,293,044        8.52 分      1.78%
IFR         492,421       15.76 分      3.26%
LIFR        344,515       17.83 分      3.52%
```

天氣從好到壞，延誤與取消率單調上升，「實際氣象 vs 自我回報」的落差
算得出來。

**可套用的方法**：低報程度的量化與排序、實測氣象的劑量反應、
機尾號串接當日航段做延誤傳播、起降機場構成有向網路。

**代價**：完整版 6.1 GB；`oracle_` 欄位絕對不能進預測模型；
結果變數強右偏。

**台灣做不了這題**——不是資料難拿，是台灣沒有「航空公司自報延誤成因」
這個欄位。民航局只有月彙總 XLS/PDF，TDX 只有班表與即時資訊。
少了自報這個對照基準，低報稽核這個題目不存在。

## 2. 候選 J — 2020 美國大選逐張選票

https://dataverse.harvard.edu/dataset.xhtml?persistentId=doi:10.7910/DVN/PQQ3KV

> notebook：`候選 J` 節

**研究問題**：選民在同一張選票上跨層級的投票組合呈現哪些型態？
分裂投票的比例與結構為何？能否用個體資料檢驗郡層級彙總推論的生態謬誤？

| | |
|---|---|
| 發布者 | MIT Election Data and Science Lab (MEDSL) |
| 論文背書 | Nature *Scientific Data* (2024) |
| 筆數 | 166,470,734 列，4,270 萬名選民、20 州、逾 2,200 位候選人 |
| 時間 | 2020 年大選，單一時點 |
| 授權 | CC0（已確認） |

**實測結果是所有候選裡最乾淨的**：列數與論文宣稱**差異 0**。
分裂投票結構真實可觀測——搖擺州 857 萬票中有 13.9 萬張（1.62%）反向分裂。

「個體層級 × 多重選擇」的結構在我們評估過的候選裡獨一無二。

**可套用的方法**：潛在類別分析或對應分析萃取投票型態、選民巢狀於
選區郡州的多層次模型、跨層級選擇的對數線性模型、生態謬誤的正面檢驗。

**限制**：這是選舉研究社群自己發布的資料，CC0 誰都能下載，MEDSL 已經
發過 Nature 子刊——我們沒有他們拿不到的東西。另外 `precinct` 欄缺失 28%
（多層次模型第二層只能退到郡）、`GOVERNOR` 只有 3 州、無時間維度、
20 州非隨機（不可宣稱代表全美）、政治主題須嚴守中立。

**有意思的是台灣做不了這題反而是它的論據**：台灣最細的粒度是投票所
彙總，不存在逐張選票紀錄——這是制度差異。而投票所彙總正是生態謬誤的
來源，不是解方。

## 3. 候選 N — 台灣道路交通事故

https://data.gov.tw/ → 內政部警政署（A1 類 / A2 類事故資料）

> 尚未實測

**研究問題**：控制道路環境、天候、光線與時間後，哪些當事者特徵
（年齡、性別、車種、保護裝備、飲酒、手機使用）對傷亡程度的影響最大？
肇事逃逸的決定因子為何？

| | |
|---|---|
| 取得 | 直接下載 CSV，**無需申請** |
| 筆數 | A1 類 2,587 列；A2 類單月 80,620 列，推估年約 100 萬列 |
| 欄位 | **51 欄，且已完全解碼**（直接是「雨」「市區道路」等中文值） |
| 授權 | 政府資料開放授權條款 |

**台灣候選裡受益者最明確的**——道安會與地方交通局，保護裝備、速限、
路口設計的邊際效果都是可操作的建議。

資料結構的優勢：有經緯度可做空間統計；**當事者巢狀於事故**是天然的
兩層結構（同一事故的當事者共享環境條件，違反獨立性，必須用多層次模型），
這一點使它在方法論上優於候選 A。

**可套用的方法**：次序邏輯斯迴歸（傷亡程度為序位）、多層次模型、
空間熱點偵測、保護裝備 × 車種等交互項、道路環境類別變數的多重對應分析。

**限制**：A2 類分散在 9 個 ZIP 要寫腳本串接；「即時」資料只涵蓋當年度，
多年分析須確認歷年版本；**無分母**（有事故數但無車流量，算不出事故率）；
CSV 末尾有兩列中繼資訊讀取時要排除；編碼是 UTF-8 with BOM。

## 4. 候選 C — BRFSS 美國成人健康行為

https://www.kaggle.com/datasets/cdc/behavioral-risk-factor-surveillance-system

> notebook：`候選 C` 節

**研究問題**：控制個人社經與人口特徵後，各州在健康風險行為
（吸菸、身體活動不足、預防服務使用率）上的差距有多大？

| | |
|---|---|
| 原始出處 | CDC BRFSS 年度資料 |
| 筆數 | 每年逾 40 萬份成人訪問，2011–2015 共 5 年，解壓約 2.9 GB |
| 授權 | CC0 |

**這是全部候選中唯一能正當做複雜抽樣加權估計的資料。** 實測確認七個
設計變數五年皆完整、權重零缺失、1,306 個分層**無單一觀測層**
（有單一觀測層的話變異數估計會失效）。

**可套用的方法**：分層 + 群集 + 權重的加權估計、州為第二層的多層次模型、
無反應機制分析、高維類別變數的變數選擇、跨 5 年趨勢。

**有個坑值得提，滿容易中的：**

```
_HCVU651 的值分布
  1.0  →  252,542
  9.0  →  159,253    ← 碼 9 = 不知道／拒答
  2.0  →   29,661

null_count = 0
```

BRFSS 把「不知道／拒答」編成碼 9，是有效整數不是 null。
`null_count` 回報 0%，看起來完全沒缺失，實際上這欄 36% 是無效回答。
直接拿去算平均會得到一個看起來很合理的錯數字。

**限制**：同樣沒有資訊優勢（BRFSS 公開多年、文獻極多）；轉檔保真度有
未解落差（吸菸率實測 16.72% 對比 CDC 公布 17.5%，差 0.8 個百分點）；
資料停在 2015；共同欄位僅 158 欄，其中 59 欄缺失率 ≥70%（分州選作模組）。

台灣有結構相當的（國健署健康行為監測、國衛院 NHIS，分層+群集+權重
三者皆備），但**必須經衛福部資科中心申請**：依附學術機構、審議會審查、
赴研究分中心現場分析、原始資料不得下載。流程以月計，時程不相容。

## 5. 候選 H — PJM 電網負載 × 氣象

https://www.kaggle.com/datasets/arimancy/pjm-hourly-demand-weather

> 尚未實測

**研究問題**：電力需求中有多少可由氣象解釋、多少屬於資料中心帶來的
結構性成長？冬夏雙峰的氣溫反應函數形狀差異為何？

| | |
|---|---|
| 上游 | EIA-930 經 PUDL 清理 + EIA API + Open-Meteo ERA5 + Census 人口權重 |
| 筆數 | 97,850 小時（2015-07 至 2026-08，11 年），**UTC 軸上無缺漏** |
| 規模 | 54 MB，parquet 與 CSV 皆有 |
| 授權 | CC BY 4.0 |

**這次我把它往上調了。** 原本排很後面是因為「負載預測的使用者是調度
單位，資訊遠多於公開資料」——但負載預測不是這份資料唯一能做的題目，
而且是最不該做的那個。

它真正撐得起的是**氣象效應與資料中心結構性成長的分離**。PJM 作為市場
營運者，對「新增負載有多少來自資料中心」做公開歸因會牽動成本分攤與
併網排隊的爭議，**沒有動機自己做**。受益者是 FERC 與州監理單位，
不是調度單位。這個結構跟候選 I 同類。

**資料品質是所有候選中最高的**：所有插補與初步值都有旗標
（`demand_source`、`weather_is_preliminary`、`temp_is_missing`、
`is_dst_transition_day`），連夏令時轉換日都標出來。跨年比較需要的條件
是逐項備妥的。

**可套用的方法**：氣溫的非線性反應（U 形，冬夏雙峰）、趨勢與季節分解、
多重季節性時間序列（日內／週內／年度）、極端事件分析（Winter Storm
Elliott 與 2025 年 1 月寒潮都在範圍內）、變點偵測。

**限制**：第三問靠立場而非資料獨佔（誰都能下載做同樣分析）；
**無空間維度**（RTO 全區總量，非分區資料）；ERA5 是再分析不是測站觀測；
所有需求特徵至少落後 24 小時，違反會造成看似優異實則無效的結果。

# 四、幾個踩過的坑

- `null_count` 是 0 不代表沒缺失。BRFSS 把「不知道／拒答」編成碼 9，
  是有效整數，`_HCVU651` 這欄 36% 是無效回答但 `null_count` 回報 0
- 不要假設叫 id 的欄位全域唯一。候選 J 的 `cvr_id` 只在郡內唯一，
  單欄去重低估 5.5 倍
- 聚合前檢查字串拼法。`JOSEPH R BIDEN` 與 `JOSEPH R. BIDEN` 差一個句點，
  直接 group_by 低估 17%
- 欄位名稱不等於語意。實價登錄的屋齡存西元年；台電的「中送北潮流」
  82% 時間為負，名稱講的是量測慣例不是實際流向
- 欄位相加恆為常數、相關係數接近 ±1，是合成資料的指紋
- 跨年比較前先分年看各組樣本數與組內構成，不要只看總列數
- polars 的瓶頸是分組數不是列數。1.66 億列全掃 0.1 GB，
  但 4,620 萬組的 group_by 撐爆 16 GB
